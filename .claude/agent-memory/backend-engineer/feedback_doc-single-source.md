文档（`docs/**`、各 README）里凡提到**有单一真源的值** —— 后端版本号、宿主端口、模型清单等 —— 按三档处理：

1. **硬断言 / 判据 / 字段来源说明** → 写「**等于 <真源>**」，并给出**可直接粘贴的取数命令**
   （例：版本号 = `cd /mnt/c/wp/nexus-agent-workbench && grep -o '<revision>[^<]*</revision>' backend/pom.xml`）。
   不要写成「等于某个具体版本号」。
2. **示例 JSON / 响应样例** → 保留字面量（示例要可读），但必须在样例附近**显式标注**：
   「**示例值，非真源；实际以 `/api/health` 的实际返回为准**」。
3. **文件名示例**（如 jar）→ 改成通配（`nexus-start/target/*.jar`），去掉版本号。
   注意 README 里那条 PowerShell 不展开通配符的提示，要保留提示、去掉具体版本号。

**How to apply:** 起草或修订文档时。**不要**为了"不写死"而把判据弱化成通用正则 ——
semver 正则只挡「占位符 `@..@` 没被替换」这类格式缺陷，挡不住「值改了、产物却没跟着变」。
正则可以留，但必须同时要求「与真源取值比对相等」。

**Why:** 2026-09-15「清理文档里写死的后端版本号」任务，用户亲自给出这三档口径，并特别点名：
退化成 `^\d+\.\d+\.\d+$` 会丢掉**「改了版本号、产物却没跟着变」这条唯一能抓住版本漂移的判据**
（实景：父 POM 0.2.1 / 子模块 0.2.0，构建成功且零警告，产物仍是旧版 —— 详见 `docs/design/00-环境与部署.md` §5.1）。
真源本身（= `backend/pom.xml` 的 `<revision>`）已写入 CLAUDE.md，此处不重复；本条记的是**文档怎么写**。
