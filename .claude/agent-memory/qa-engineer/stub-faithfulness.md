**规则**：给脚本做离线干跑的**桩后端/桩 docker**，要按**契约文档**（`docs/api/README.md`）的语义写，
**不能按源码里"顺手实现的那部分"写**。桩里每少一条判定，就等于给被判对象开了一个后门。

**Why**：2026-09-17 干跑 `tc01-logout-then-me.sh`（TC-01-1.2-5）时踩到：桩的 `/api/auth/logout`
一上来就删键、**没过「过滤器三步」**，于是"幂等重登出"回了 **200**；而契约 §5.3 白纸黑字写的是
「无 token / **已失效** → HTTP 401 + 40100/40101」，真实后端也确实是过滤器先拦（logout 不在白名单里）。
这一处不忠**恰好掩盖了该用例清理段要说明的行为**（"键已不在 ⇒ 后端回 401，不是失败"）——
干跑输出看着一切正常，是我逐行读输出时才发现的。桩不忠 → 干跑给的"通过"是假的。

**How to apply**：
- 桩落地前先把契约里**每个接口的成功/失败形态**抄成一张清单，逐条实现（含"已失效"这种非主路径）。
- **逐行读一遍干跑输出**，不要只看退出码和关键行 grep —— 上面那个 bug 就是退出码全绿时藏着的。
- 桩复刻判定**顺序**也要照契约（如认证三步：签名+有效期 → 白名单 → 业务查询），顺序错了会串码
  （1.2-3 的 40102 会被串成 40101）。
- 桩里的日志行要能与真实后端同形，否则日志佐证类判据（如 1.2-5 的 ③/② 分流）在干跑里验不出来。
- 相关：[[criteria-falsifiability]]（假通过清单）、[[fixture-cleanup-claims]]（干跑抓出的另两个真 bug）。
