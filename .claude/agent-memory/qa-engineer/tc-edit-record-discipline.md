**规则一：删除 TC 用例，禁止静默删。** 一条用例被删掉时，必须同时留下两处痕迹：
① 文末「附：已知的『测不出来 / 不做』与为什么」表**新增一行** —— 写清**原编号、移除时间（绝对日期）、为什么移除**；
② 编号对照/小节处注明**空号**。**编号保留空号、绝不重排**（重排会让 agent-log、记忆、commit 里的历史引用失锚）。

**规则二：「手工形态跑过」与「脚本形态跑过」是两件事，不能互相顶替。** 步骤栏改成脚本后，
**旧的通过记录不能给新脚本结案**；脚本形态没跑过就照实标出来（统一标记 + 一处理解它的图例，别逐行拉长表格），
且「实测」栏**保持空白**（空 = 本文件未记录任何观察，不是"没过"）。回填时**必须注明是哪种形态的观察**。

**Why**：2026-09-18 用户手工验收 TC-01 时提的两条意见。原话（经主会话转达的硬要求）——
「**不要静默删**……目的：将来有人看到 `@IgnoreTenant` 想再补一条用例时，能看到**这条已经评估过、结论是不做**，
而不是面对一片空白」；脚本那条 —— 「新改的脚本，你需要标注一下，以后有时间再跑，因为**我已经手工验过逻辑了**」
（即：他验的是**旧手工形态**，脚本形态仍未跑）。措辞要让人看懂**不是漏了，是评估过**。

**How to apply**：
- 删任何条目**之前**先问两句：**它证的东西有没有被别的用例覆盖？**（覆盖它的是谁、在哪一行）**覆盖不了的那部分有没有别的落点？**
  答不上来就别删，改成"这条不做了"写进附录而不是从表里抹掉。本次两条就是这么过掉的：
  `@IgnoreTenant`「是否生效」由 fail-closed 机制转给登录用例（豁免失效 → SystemException → 登录 500 → 1.4-1 当红）；
  「有人多加了豁免」这个真危险场景由跨租户 token 用例抓（隔离失效时它会回 200 而不是 401）。
- 附录条目的验收标准是**读者不依赖上下文也能读懂**：写得下就写，宁可长一点也别留一个光秃秃的编号。
- 顺带核对**跨文档引用**：design/task 的验收项编号与本文件用例编号是**两套东西**（见 TC-01 头部「编号对照」），
  删一条用例可能让**某个验收项在本文件里再无落点** —— 那要在头部编号对照里点明它落到哪条用例上。
- 删除动作也可能**暴露原有措辞的缺陷**（本次：被删那行点名的单测其实不覆盖它声称的分支）——
  顺手把订正写进附录，别把错的说法原地留下。
