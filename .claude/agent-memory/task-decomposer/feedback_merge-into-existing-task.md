收到一份新草稿时，先判断它对应**哪个阶段**；若草稿讲的是已有子任务（如 `task.1` 里的 `0.3`），就**细化进现有 `docs/task/task.N+简称.md`**，不新建文件。

**Why**：本项目的拆解规范（`.claude/skills/task-decompose/SKILL.md`）是「**每个阶段一个 task 文件**」，task 编号与阶段号一一对应（阶段0→task.1 … 阶段4→task.5）。`docs/drafts/环境检查脚本.md` 讲的是环境检查脚本，而 `0.3 环境检查与一键启动脚本` 已在 `task.1` 中占位 —— 另起一个文件会破坏「编号 = 阶段」的对应关系，也会让同一子任务出现两个事实源。

**How to apply**：
1. 判定阶段归属 → 找到对应的 `task.N` 文件 → 在原子任务号（`0.3.1`、`0.3.2` …）下展开，保持父级编号 `0.1`/`0.2`/`0.3`/`0.4` 不变；
2. 阶段内新增子任务不超过 5 个；已完成 / 未开工的兄弟子任务**原文不动**；
3. `docs/核心任务.md` 遵守**最少修改**：只改进度行、只在阶段小节末保留**一个**文件链接，不改写原文；若决策会影响交付物清单，先写进 task 文件的「待确认事项」，不要抢先改作战地图；
4. `docs/drafts/` 原文**不动、不删、不改**，修正结果写进正式文档，并回引草稿路径说明订正了哪些条目。
