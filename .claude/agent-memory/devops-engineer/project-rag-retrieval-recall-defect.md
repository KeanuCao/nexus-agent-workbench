2026-09-22 阶段3 端到端验收（走 8088）**未通过**：上传 `公司年报.pdf`（263,910 字 / 587 块）后问「去年利润是多少」，
`grounded=true` + 5 条引用，但**答案固定是「知识库中未找到相关内容。」**，3 次复现完全一致（非偶发）。

**已排除**（这些都不是原因，别再查一遍）：

| 假设 | 实测反证 |
| --- | --- |
| 入库没加任务前缀（`search_document:` / `search_query:` 不对称） | `cos(存库向量, embed('search_document: '+原文)) = 1.000000`，前缀对称且生效 |
| 生成侧坏了 / 没调通 DeepSeek | 换问「受益计划的平均服务年限是多少年」→ 答「…27.4年…[资料1]」，数字与原文一致 ⇒ 检索→生成整条链路是通的 |
| 解析质量差（Tika 没抽出财务表） | `pdftotext -layout` 抽出同一份正文里 `84.1 亿元`(×2 处) 与 `8,408,057 千元`(财务报表形态) 都在 |
| 阈值把答案筛掉了 | 恰恰相反：阈值 0.5 **一条都没筛掉**，5 条全是无关块（score 0.71~0.75） |

**根因（有数字）**：`nomic-embed-text` + 500 字分块的中文召回不足 ——
含答案的分块（`84.1`/`41.2%`/`8,408,057`）在 587 块中的最优排名：
问「去年利润是多少」= **第 27 名**；问「归属于上市公司股东的净利润是多少」= **第 47 名**；
只有把问题写成「报告期内公司实现的营业总收入是多少」才进得了 top-10。
而 top-5 命中的无关块 score 高达 0.71~0.75、`S_miss`（"今天杭州天气怎么样"）也有 **0.6929**
⇒ **`(S_miss+S_hit)/2 ≈ 0.72` 这类"标定阈值"救不了它**，因为无关块比阈值高得多、答案块连前十都进不去。
检索质量是排序问题，不是阈值问题。

**Why:** 这是"阶段验收标准（task.4 3.5：上传年报提问去年利润能准确回答）"当前**唯一不成立的判据**；
TC-03-4.1 / 3.5 / 4.5 的实测栏都还空着（阈值标定五步从未跑过）。误诊成本高：会有人先去查解析、查前缀、查 DeepSeek。

**How to apply:** 讨论修复方向时从这几条里挑（都不是"改个阈值"）：分块粒度（500 字对中文财务表太粗）、
把问题原文直接与 `content` 做混合检索（关键词/BM25 或 pgvector 全文）、换中文向 embedding 模型（如 bge-m3 类）、
或 `topK` 放大后重排（rerank）。**改任何一项（分块参数/embedding 模型/前缀）后必须重传文档再复测**——
本轮不保存原件，旧向量不会自动更新。复测口径见 `docs/test-cases/TC-03.md` 3.5 / 4.1。
相关：[[project-mirror-daocloud-verified]]、[[project-wsl-tooling-facts]]

### 2026-09-22 深夜：**阶段2 复测结果 —— 召回缺陷已实质解决，但验收判据仍不成立，且失败原因换了一个**

**实测（同一份年报重灌 587 块 / 1024 维 / 上传 129.75s）**：

| 问题 | nomic 排名 | bge-m3 排名 |
| --- | --- | --- |
| 去年利润是多少 | 27 | **4** |
| 归属于上市公司股东的净利润是多少 | 47 | **1** |
| 报告期内公司实现的营业总收入是多少 | 10 | **3** |

⇒ `[4,1,3]`，**"进前 3" 判据差一名**（"去年利润是多少" 排 4）。但**判据比应用实际要求更严**：应用 `topK=5`，
rank 4 的答案块（chunk 195）**每次都被检索到并作为引用返回**。无关问 top1 由 0.6929 降到 **0.4218**
（相关带 0.61~0.71 vs 无关带 0.39~0.42 ⇒ 阈值 0.5 这才第一次有真实分离带，D9 标定可做了）。

**★ 新的、更重要的观察：失败原因已从"检索"换成"问法歧义 + 答案不确定"**
- 同一条查询串 `去年利润是多少` 连问两次，**答案不同**：
  第一次 `2024年度利润总额 6,907,770 / 净利润 6,092,538`（上期列），
  第二次 `2025年净利润为 8,487,650 千元（约 84.88 亿元）`（本期列，但取的是"净利润"不是"归母净利润"）。
  两者都**不含**验收要的 `84.1 亿元` / `8,408,057 千元`。
- **换成无歧义问法**（`报告期内归属于上市公司股东的净利润是多少千元？`）**当次就答对**：`8,408,057 千元 [资料1][资料5]`。
- 机制（有原文）：`净利润表` 被 500 字窗口切开 —— **列头 `项目 附注 2025年度 2024年度` 落在 chunk 193**，
  而数字行落在 chunk 194/195；检索命中 194/195 **没命中 193** ⇒ 模型拿到两列数字但没拿到"哪列是哪年"的表头
  （chunk 195 原文里 `四、利润总额 … 9,907,171 6,907,770` / `1.归属于母公司股东的净利润 8,408,057 5,955,567` 都是两列并列）。
- ⇒ **§10.3 的"混合检索 / rerank"救不了这一条**（答案块已被检索到并被引用）。真正对症的是**表格感知 / 语义分块**
  （别把列头和数据行切散），外加**验收问法要写清口径**（哪一年 × 哪个利润口径）。
- ⚠️ 副作用提醒：**答案不确定 ⇒ 任何断言答案精确串的验收用例都会 flaky**，qa 的 TC 要注意。
