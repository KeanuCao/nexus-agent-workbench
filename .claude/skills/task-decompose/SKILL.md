# 任务拆解（task-decompose）

把一份任务草稿拆解为「作战地图 + 分阶段拆解文件」两级文档。适用于本项目"规范 + 任务"分离的文档体系。

## 文档体系约定（背景）

| 文档 | 角色 | 规则 |
|------|------|------|
| `CLAUDE.md` | 宪法：技术栈、编码规范、任务执行协议（L1/L2/L3 分级） | 不在其中重复维护任务清单 |
| `docs/核心任务.md` | 作战地图：阶段划分、交付物、当前进度 | **保持原结构，不大改** |
| `docs/task/task.N+任务简称.md` | 各阶段的详细拆解（子任务、验收标准） | 每个阶段一个文件 |
| `docs/drafts/` | 存档区 | **原文不动、不删、不修改** |

## 工作流程

### Step 1：阅读输入
1. 读取任务草稿（通常在 `docs/drafts/` 下）。
2. 阅读 `CLAUDE.md` 的任务执行协议，确认任务分级（阶段 = L1 阶段级；子任务内单文件改动 = L3）。
3. 确认拆解粒度：**每个阶段一个 task 文件**，阶段内拆 ≤5 个子任务。

### Step 2：生成 `docs/核心任务.md`（作战地图）
**原则：不要大改草稿**——保留草稿原有标题和全部条目原文，只做三件事：
1. 顶部加简短说明（作战地图定位 + 指向 `docs/task/` 目录）。
2. 加「📊 当前进度」段：逐阶段列出状态，全部初始为 `⏳ 待开始`；并注明状态标记体系（⏳ 待开始 / 🚧 进行中 / ✅ 已完成）。
3. 每个阶段小节末尾**最多加一行**（一个文件链接 + 状态）：
   ```
   > 📋 详细拆解：[`docs/task/task.N+简称.md`](task/task.N+简称.md) ｜ 状态：⏳ 待开始
   ```

### Step 3：生成 `docs/task/task.N+任务简称.md`
- **命名**：`task.N+任务简称.md`，N 从 1 开始按阶段顺序编号（阶段0 → task.1，阶段1 → task.2 …），简称取阶段名（如 环境准备、多租户认证、统一AI网关）。
- **文件结构**（每个文件固定包含）：
  1. 头部引用块：任务级别（L1 阶段级）、状态、设计文档路径 `docs/design/<阶段号>-<模块>.md`、测试案例 `docs/test-cases/TC-XX.md`。
  2. `## 任务目标`（一句话，取自草稿阶段目标）。
  3. `## 执行要求`（L1 流程：先出设计文档 → 等确认 → 编码 → 更新 `docs/核心任务.md` 进度 → 生成 TC-XX）。
  4. `## 子任务拆解`：每个子任务写清四项：
     - **输入**：依赖的产物或前置子任务编号（跨阶段依赖用 `task.N 的 X.Y` 标注）
     - **输出**：具体文件/类/接口路径
     - **依赖**：子任务编号
     - **验收标准**：可验证的具体标准（能执行的命令、能观察到的行为），不写口号
  5. `## 🚩 阶段交付物`（对照草稿的交付物条目）。
  6. `## ✅ 阶段验收标准`（阶段整体可演示的验收）。
  7. `## 完成状态`：`- [ ]` 勾选清单，每项 = 子任务编号 + 名称。

### 编号约定
- task 文件编号：阶段 0~4 对应 `task.1`~`task.5`。
- 子任务编号沿用阶段号前缀：`0.1`~`0.4`、`1.1`~`1.5` …
- 测试案例：TC-00 对应阶段0，依此类推。
- 设计文档：`docs/design/00-环境与部署.md`、`01-多租户与认证.md` …（阶段号-模块名）。

## 注意事项
- 草稿位于 `docs/drafts/` 时**不要动草稿**，拆解结果写入 `docs/` 与 `docs/task/`。
- 核心任务.md 保持"最少修改"：不加多余章节、不改写原文、每阶段最多一个文件链接。
- 验收标准必须可执行、可演示（面向面试展示场景）。
- 全部文档用中文，行文风格与 `CLAUDE.md` 一致。
- 拆解完成后向用户展示：新文档结构 + task 文件编号与阶段对应表 + 草稿保持不变。
