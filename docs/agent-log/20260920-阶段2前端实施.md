## 遇到的坑

1. **★ 第一轮撞 35 轮上限被中断，且未交报告。**
   主会话只看到"部分结果、无报告"。恢复后才发现**代码其实已基本写完**（4 个新文件都在），只是没来得及汇报。
   → 处理：主会话恢复时明确要求「**若估计又要撞上限，先把"做到哪了 + 还剩什么"交回来** —— 一份状态报告远比一个没报告的半成品有用」。第二轮顺利完成并交付完整报告。
2. **★★ 「（已停止）」这类标记若按设计字面"追加进正文"，会被喂回模型。**
   设计 §5.4 写的是"保留已吐出的文本，追加「（已停止）」标记"。但下一轮 `messages` 是**全量上送**的 —— 标记若进了 `message.content`，就会被当作模型输出送回上游，而这正是 §5.5 想避免的事（"避免把半截文本喂回模型"）。
   → 处理：做成气泡的**独立展示字段**（`note` / `model` / `streaming`），不进 `content`。**这是对设计的必要澄清，不是偏离。**
3. **EOF 且无终止帧时，刻意不臆造 `20100`。**
   设计 §6.3 只说"按 error 展示通用文案"。agent 用 `code = null` + "连接已中断（未收到结束帧），本次回答可能不完整"。
   理由：若图省事填 `20100`，会把"网络断了"**误报成"模型服务不可用"**，把排查方向带偏。
4. **设计 §5 的"type-only import、不引入运行时耦合"与 D4 的"复用同一套解包/成功判定"互相拉扯。**
   判别联合要求 `data` 是**已解包的载荷**，解包必须判 `code` 与形状 → 不 import 就得在 `sse.ts` 另写一份形状判定，而那正是 D4 要消灭的漂移。最终选了运行时 import（代价：sse.ts 连带 axios 实例与 ElMessage，本就在同一 bundle 里），并给出备选（新建零依赖的 `api/result.ts`）交主会话拍板。
5. **`TS18047: 'data' is possibly 'null'`（4 条，`sse.ts` 的 done 分支）。** 靠先 `if (!data)` 收窄再取值修掉，复跑确认。**注意：本阶段不引 Vitest，这类错误唯一的拦截点就是 `type-check`** —— 它跑不跑得起来，决定了这批代码是否有任何自动化门禁。
6. **契约里 `delta` 帧没有 schema**（`openapi.yaml` 只有 meta/done/error，而帧表里有 `data.content`）→ 机器可读版与帧表**不一致**。agent 补了 `ChatStreamDelta` 并注明出处，同时**按纪律上报**而非默默补上。已由主会话转给后端补。
7. **中文输入法下的回车**：不判 `event.isComposing` / `keyCode === 229` 会把候选词框卡住 —— 设计文档完全没提，是实现经验补的。

## 下次怎么改进

1. **长任务要在开工时就把"报告预算"留出来。**
   本次第一轮把所有轮次花在实现上，导致"没报告的半成品"——**代码写完了，但接手的人不知道写到哪、有没有中间态**。
   判据：**预估轮次用掉 80% 时就先交一份状态报告**（做到哪、还剩什么、有无半成品）。宁可报告短，不可没有。
   配套：恢复被中断的 agent 时，第一条指令就要包含"若又要撞上限，先交状态再停"。
2. **设计文档描述 UI 文案时，必须同时说明它是否进入"会回传给模型的数据结构"。**
   本次坑 2 的根因是：设计只说了"追加标记"，没说"追加到哪"。而在这个页面上，**"显示给用户"与"发给模型"是同一份 `messages` 数组** —— 这是对话类界面的通用陷阱。
   判据：**凡 UI 文案要落在 `messages`/`history`/`prompt` 这类结构上时，设计里加一句"该字段是否参与下一轮上送"。**
3. **契约里每一种事件/帧都要有对应的 schema，且要与帧表逐项对照。**
   openapi 漏掉 `delta` 的根因是：帧表是给人读的、schema 是给机器读的，**两者分开维护就会漂**。判据：**帧表每加一行，就问一次"机器可读版里有对应 schema 吗"。**
4. **能把"注释纪律"升级成"类型强制"的，就升级。**
   本次 `onAborted` 与 `onError` 做成**两个独立回调**，使"catch 里必须按 `AbortError` 分流"从一条注释变成了**调用方无法违反的类型约束** —— 比写十行注释可靠。判据：**凡是"实现时容易忘"的约定，先问能不能用类型表达。**
5. **`type-check` 在无单测阶段就是唯一门禁，必须当作硬性交付物。**
   本次 4 条 `TS18047` 就是它拦下的。判据：**前端交付物的"完成"定义里必须包含 `type-check` 的实际输出**，而不是"我写完了"。
