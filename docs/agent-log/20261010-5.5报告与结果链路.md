## 遇到的坑

1. ★ **"空卷"其实不空**：Docker 首次挂载命名卷时，会把镜像里对应目录的内容**拷进空卷**
   （发现俩 2025-04-16 的 nginx 欢迎页）。⇒ "卷里什么都没有"这个前提不成立；处置：发布步骤做
   **整树替换**（不假设卷内状态），落地页补上"本次结论"。
2. ★ **"结果表放 `db-patch/`"会建错库**：实测发现 `db-patch` 链（PatchCli）打的是**应用库 `nexus`**
   （用 builder 的 `NEXUS_PG_*`）⇒ 原候选 (a) 会把测试基础设施表建进应用库。这条把"落位 (b)"从
   "偏好"变成了**实证结论**。
3. **宿主工具的假设必须逐个 `command -v` 实测**：测试宿主**没有** java / javac / node / npm / allure /
   unzip（有 curl / wget / git / python3.12.3）⇒ Allure CLI 的下载与解压全自己来（urllib + zipfile），
   JDK 借 builder 镜像。
4. **WSL 墙上时钟会倒退**（它打出过 "-0.3s 用时"）⇒ 计时一律 `time.monotonic()`（环境级事实）。
5. **红线内怎么取证**（正面范例）：不许动真卷 / 不许重启容器 ⇒ 它在**备用卷**
   （`nexus-test-report-selftest`）上做全链预演、验完删卷；对结果库的幂等写用
   "伪造一次失败运行 → 验证 → 删除"闭环。**验证边界被收窄时，仍然能给全链证据。**
