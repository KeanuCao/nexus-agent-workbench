## 遇到的坑

1. ★ **"插值正确"≠"容器已吃到"**：`config` 只证明渲染；env 只在容器**创建时**注入 ⇒ 真证据要等
   `deploy_test.py --profile test` 重建 backend 容器后、由 S5 实跑给出。它把这条边界**写明**了
   （没把 config 通过说成"修好了"）—— 这个口径值得固化。
2. **反向探针的必要性**：只验"键出现了"无法区分"值来自 `.env.test`"还是"来自 `:-OLLAMA` 默认值"；
   后者会让"改了 .env.test 却没生效"继续静默。反向探针（故意改错值、看渲染是否跟随）是
   「同一结果两个来源」类问题的通用证法。
3. **派活时引用文档位置别凭印象**：任务书写「TC-05 §0」，实际在 §1 行 ⑦ —— 执行者按实际位置处置并上报
   是对的，但这一轮本可避免。
4. **测试工具的副作用也是副作用**：跑一次 pytest 就会覆盖 `artifacts/` 里上次的结果 ——
   在"只做修复"的任务里，主动避开它（改用模块级校验）是自觉行为。
