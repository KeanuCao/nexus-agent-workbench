- **Agent**：backend-engineer ｜ **耗时**：约 14 分钟 + 续跑约 16 分钟 ｜ **task-id**：无（本段由主会话手工留档）

  根因是**中文检索召回不足**（答案块在 587 块中排第 27 名，无关块也拿 0.71~0.75 分；四个替代假设已被

## 做了什么

**第一轮（换模型的四处改动）**
1. `rag/embedding/OllamaEmbeddingService.java`：`EMBED_MODEL` → `bge-m3`、`EXPECTED_DIMENSION` → `1024`；
   字段与类注释重写（带上全套诊断数字与已排除的四条假设），并写明"两者必须同改"的双向后果。
2. `nexus-start` 的 `application.yml`：`nexus.ai.rag.document-prefix` / `query-prefix` → **空串**
   （`search_*:` 是 nomic 模型卡的建议，bge-m3 不期望），注释说明"必须与换模型同一次改"。
3. **新增破坏性补丁** `db-patch/202609221100_知识库向量维度改1024.sql`：DROP 子表 → DROP 父表 →
   按 `202609221000` **原样重建**（只把 `vector(768)` 改 `vector(1024)`，含 HNSW 余弦索引与全部 COMMENT）。
   头部写全六件事：数据会丢、为什么不能 `ALTER COLUMN TYPE`、与代码的配对、执行顺序、执行后的两条只读判据、回滚方式。

**第二轮（主会话复核后的收口）**
4. `RagProperties` 的两个前缀**默认值**由 `search_*: ` 翻成 `""`（理由见「遇到的坑」3）。
5. 四处旧模型残留注释改净（`EmbeddingService` / `UpstreamEmbedRequest` / `KbChunkMapper` / `OllamaProbe`），
   全局 grep `nomic|768` 逐条确认为"历史性/解释性说明"（唯一独立的 `768` 是 `OllamaService` 的 `32_768` 上下文长度）。
6. 补丁改名（去空格）后，把它自己留下的 4 处旧名引用一并改掉；全仓 grep 旧名 → **0 命中**。

## 遇到的坑

1. ★ **换模型是"牵一处动全身"，四处清单缺一不可 —— 而它的两种后果都很难查**：
   · 只改模型不改维度 ⇒ **建表成功、第一次入库才报类型错**（极易误判成代码 bug）；
   · 只改维度不改模型 ⇒ 本类校验先抛系统异常（这个反而是响亮的）；
   · 忘了清前缀 ⇒ **不报错、只是检索变差**（静默劣化，本仓库最防的形态）；
   · 忘了 `docker-compose` 的 `ollama-init` 清单 ⇒ 每次向量化 `model 'bge-m3' not found` ⇒ `20100`（响亮）。
2. **`1024` 是"公布值"而不是"本机实测值"**：换模型时容器里还没有 bge-m3，探针无从跑起。
   处理：取 `BAAI/bge-m3` 的 `config.json`（经 HF 镜像）→ `hidden_size: 1024`（xlm-roberta 架构，稠密检索向量即 hidden_size）；
   并在**代码注释与补丁头部都如实标注"未实测"**，同时给出**顺序要求**：
   `改 ollama-init 清单 → 拉 bge-m3 → 探针 A（期望 1024）→ 执行补丁 → 重启 → 重传`。
   **补丁未执行时可以改**（改了 vector(N) 与常量即可）；**执行过就只能再新增一个补丁**（代价是又一次清库）——
   这条"顺序错了要付什么代价"写进了补丁头部，是本段最有价值的一句话。
3. ★ **默认值会在"清理配置"时静默复活**（子代理主动上报的陷阱）：`RagProperties` 的字段默认值仍是
   nomic 的前缀，靠 yml 显式 `""` 覆盖 ⇒ 一旦有人"清理"那两行 yml，**前缀会悄悄回来**，检索质量随之劣化
   且不报错。处理：把**默认值本身**翻成 `""`（默认值应当与当前决策一致），注释同时写清
   "机制保留（换回需要前缀的模型时把值填回去）、默认置空的理由是当前模型不需要 —— 不要顺手把机制删掉"。
4. **测试里的镜像常量与生产同源**（子代理上报、转 qa 修）：`OllamaEmbeddingServiceTest` 的 `DIMENSION=768`、
   负样本 `767`、断言 `contains("768")`、以及**断言上行报文模型名的那一条** —— 生产改 1024/bge-m3 时必须同改，
   否则 `mvn -pl nexus-module-ai test` 红。qa 那侧还因此**新增了一条把当前决策钉死的用例**
   （"默认空前缀 → 文本原样发送"），将来谁把默认值改回非空就会红 —— 这是把"决策"变成"判据"的正例。
5. **我的文件名里带了一个空格**（主会话发现并改）：`…向量维度改 1024.sql`。子代理复核了引擎的正则
   （`^[0-9]{12}_.+\.sql$` + 目录扫描 + 文件名字典序）确认"不影响"，但空格会给后续所有 shell 引用添引号负担 ——
   在**补丁执行前**改名是零成本的（执行后 checksum 锁定，就动不了了）。

## 下次怎么改进

1. **把"换 embedding 模型"固化成一张清单**（本次已有雏形，值得写进设计）：
   ① 模型名 ② 维度常量 ③ DB 补丁（含数据清空声明）④ 前缀配置**及其默认值** ⑤ `ollama-init` 拉取清单
   ⑥ 脚本/契约里的期望模型名 ⑦ **测试里的镜像常量与样本** ⑧ 重灌。
   本次靠"跑一遍 + grep"补出了 ⑦ 与 ④，说明"清单不写到测试与默认值这一层"就会漏。
2. **破坏性补丁的头部该有个模板**：数据丢失声明 / 为什么不能 ALTER / 与代码的配对项 / **执行顺序** /
   执行后的只读判据 / 回滚方式。本次这份写得很好，值得作为后续破坏性补丁的样板。
3. **桩数据里的模型名要跟现实，历史说明要保留** —— 界线是"它是不是当前上游的样子"：
   `{"model":"nomic-embed-text"}` 作为**上游返回样本**已过时（改），而"2026-09-22 由 nomic 换入"作为
   **历史说明**必须留（不改）。子代理对这条界线的判断与执行都对。
