## 遇到的坑

1. **撞到 100 轮上限被截断，没来得及发汇报。**
   现象：agent 停在"Now `docs/api/openapi.yaml`"这一句。核验后发现**实际工作基本完成**（契约文件是完整的），只是汇报没发出。
   原因：任务粒度太大 —— 20+ 个新文件 + 契约文档 + 测试，一次做完超出单次会话预算。
   处理：主会话改用「读关键文件抽查决策落地 + 跑编译/测试」完成验收，不依赖 agent 自述。

2. **`mybatis-plus-jsqlparser` 是隐形必需依赖。**
   现象：`TenantLineInnerInterceptor` / `TenantLineHandler` 在 MP 3.5.9 里**不在** `mybatis-plus-extension` 中，而在被拆分出去的 jsqlparser 模块。
   原因：MP 自 3.5.9 起做了模块拆分（父 POM 在 0.4 时就预声明了它的版本，但一直没有模块真正引用过，所以从未暴露）。
   处理：模块 pom 显式引入；agent 报告称已实测 `mybatis-plus-extension-3.5.9.jar` 内无 `plugins/inner` 包。

3. **`spring-web` 与 `spring-boot-starter-web` 的区别不是风格问题。**
   现象：库模块若图省事引 starter-web，会把内嵌 Tomcat 与整条 MVC 链带进**所有**下游模块。
   处理：infrastructure / module-system 只引 `spring-web`（`OncePerRequestFilter` / `@RestController` / `MediaType` 的来源），运行期实现留在 nexus-start。

4. **`jakarta.servlet-api` 必须显式声明且 scope=provided。**
   现象：`spring-web` 6.1 的 POM 把 servlet 依赖标为可选，不显式声明则编译期找不到 `HttpServletRequest`。
   处理：显式声明 + `provided`（运行期由 tomcat-embed-core 提供同名类，不打进产物）。

5. **注释里的一处事实错误（主会话发现）。**
   现象：`TenantLineHandlerImpl` 把 `t_tenant` 的豁免理由写成「它**没有** `tenant_id` 列（主键就叫 `tenant_id`）」—— 自相矛盾。
   实际：该表**有** `tenant_id` 列，只是它是**主键**（租户自己的身份），不是"这行属于哪个租户"的判别列。
   处理：主会话改写为准确表述。**代码行为本身是对的**（确实该豁免），错的只是理由。
