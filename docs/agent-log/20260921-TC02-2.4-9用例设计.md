## 做了什么

1. **把判据钉在代码的真实出口上，而不是既有文档的措辞上**。先读后端实现判定："容器里没有密钥"时 `DeepSeekService.stream()` 抛的是 `CHAT_UPSTREAM_UNAVAILABLE`（=20100），而该调用在**工作线程**上、emitter **已开流** ⇒ **只有 `event: error` 帧一种载体**。所以备注里明确写了「**不要按"两条都算通过"写**」，并划清边界：开流前的 `Result` 20100（HTTP 503）**只属于池满**（`2.3-5`），见到它要另记。
2. **页面形态按前端实现逐条写死**（`ChatView.vue` 的 `settleRound` / `onError`）：缺密钥时 **deltaCount=0 ⇒ 走"回滚整轮"分支** —— 提问与空白回答**两条气泡都消失**、正文**放回输入框**、**气泡下方没有红字**（气泡已被回滚，没东西可挂）；红字落在**两处**且**不带**`生成失败：`前缀 —— 输入框上方的 `el-alert`（判据以它为准）与几秒即散的顶部 toast。
3. **防假通过判据（决策 D7 的要害）**：屏幕上**不得**出现任何 Qwen 回答、**不得**出现 `qwen2.5:7b` 的 tag —— 出现即 FAIL（"选了云端、跑成了本地"的静默降级）。
4. **造法自带幂等还原与双自证**：`sed` 注释掉 `.env.local` 里那一行 → `up -d --force-recreate` → 双自证（容器 `printenv | wc -c` 期望 0、文件 `grep -c '^DEEPSEEK_API_KEY='` 期望 0）→ 页面步骤 → 还原（`sed` 复原 + **再重建**）→ 双自证（期望 > 1 与 1）。
5. **§0.1 无害性总声明新增一行**：声明本用例会改 `.env.local` 一行 + 重建后端容器、**可能连带重启前端容器**，并写明"中途被打断的最坏情况"与修法。

## 遇到的坑

1. **★★ 任务书里预判的坑：`--force-recreate` 换 IP → nginx 启动期解析的 upstream 失效 → 走 8088 直接 502。**
   起因：让密钥失效**只能重建**（环境变量在**创建容器时**注入，`restart` 读不到新值）。
   处理：用例里加了两道闸 —— 第 ④ 步（停用后）与第 ⑩ 步（还原后）各验一次 `http://localhost:8088/api/health` 必须 200，不是 200 就 `restart nexus-frontend` 再验，**仍未 200 就停测**（那是链路故障，不是本条要验的 20100）。另在备注里补了一个更省事的等价做法：**前后端一起重建**（`up -d --force-recreate nexus-backend nexus-frontend`），前端重建时自然重新解析。
   顺带确认了 `2.4-4` 为什么躲得开这个坑：它用 `restart`（复用容器、IP 不变）；本条改的是 `env_file`，**只能重建**。
2. **★ 挖出一处文档自相矛盾（已上报、未自行改）**：`TC-02-2.3-4` 判据 ④ 写「气泡下方红字 `生成失败：模型服务暂时不可用，请稍后重试`」；但按 `ChatView.vue` 的 `settleRound`，缺密钥时**一个字都没吐 ⇒ 回滚分支 ⇒ 没有气泡，也就没有那行红字**。两者不可能同时成立。
   处理：新用例按**代码里的真实形态**写判据，`2.3-4` ④ **原样留着**待它实测时订正（指出矛盾 ≠ 可以自行挑一条照做）。
3. **还原也是两格，不是一格**：`sed` 只改文件，环境变量还得靠**重建**才进容器 —— 所以还原自证必须两条都查（`printenv` 证容器吃到了、`grep -c` 证文件没留下注释行）。与 `2.3-5` 同一个道理。

## 下次怎么改进

1. **造"环境态"（没有密钥 / 没有依赖 / 某个开关关着）之前，先判定这个值在哪个时刻被读取**：创建容器时注入（`env_file`）还是启动时读（配置中心/挂载文件）。这决定 `restart` 够不够 —— 本次若误用 `restart`，容器里密钥还在，用例会**假通过**（页面正常回答，被读成"没有如实报错"）。
2. **凡是要动共享依赖的用例（重建容器 = 换 IP），首尾各验一次"用户实际走的那条链路"**，并在备注里写明为什么。链路验的是 `8088`（浏览器走的），不是 `8089`（直连后端）—— 本次的坑恰好只在 `8088` 上现形。
3. **写判据前先把"这件事在代码里走哪条分支"钉死，不要从既有文档的措辞反推。** 本次正是这样挖出 `2.3-4` ④ 的矛盾：文档是按"已吐出过文本"的轮次写的，套到"零 delta"场景就错了。
