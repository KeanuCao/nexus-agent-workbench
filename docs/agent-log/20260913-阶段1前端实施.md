## 遇到的坑

1. **设计 §7 的"不在模块顶层 import store"在 ESM 里没有直接写法。**
   现象：ESM 的 `import` 语句**不能写在分支或函数体内**，而设计那句话只说了"不要在哪 import"，没说"那该怎么拿"。
   处理：改用**动态 `import()`**，把求值推迟到确有请求发出时（那时 `main.ts` 已 `app.use(pinia)`，`activePinia` 就位）。`router/index.ts` 则可用顶层静态 import —— 静态依赖图里没有回到它的边。两条边都在注释里写明。

2. **契约文档自相矛盾。**
   现象：`docs/api/README.md` §5.2 的 `data.tokenType` 字段说明**同一句里**既写"固定 `Bearer`"又写"不要硬编码"，而 §5.6 的示例自己写死了 `Bearer`。
   处理：agent 选了"用返回值 `${tokenType} ${token}`"（更贴合 §5.2 的措辞），并在汇报里**主动指出这处矛盾**。主会话随后统一了文档（§5.2 说明 + §5.6 示例同步改成实际实现）。

3. **401 时若调 `store.logout()` 会递归。**
   现象：`logout()` 会再发一次 `POST /api/auth/logout`，而此刻 token 已被服务端判为失效 → 又是 401 → 无限递归。
   处理：401 分支调新增的 `clear()`（只清本地状态，不发请求）。这个坑是 agent 自己识破的。

4. **验收 1.5-3（改坏 token → 自动登出）用常规路径复现不了。**
   现象：`/api/health` 是**白名单接口**，点健康面板的"刷新"永远不会 401；且 store 的内存值才是权威 —— 只改 localStorage 不刷新页面，根本不触发 `/me`。
   处理：agent 在汇报里明确写出该实操路径（**必须刷新页面**），主会话把它记进了 TC-01 的备注栏。

5. **守卫里调 `/me` 与"已登录访 /login 回控制台"会互相弹成无限重定向**（若 `restore()` 失败时不清状态）。
   处理：`restore()` 失败一律清空本地登录态（含"网络不通"这类非 401 失败）。代价是后端全挂时用户被请回登录页（fail-closed），已写进注释。

   本次 agent 做对了（选了更忠实的一条并主动上报），但那是自觉，不是被要求的。写进模板才会稳定复现。

2. **设计文档写前端约束时要落到 ESM 的实际写法。**
   本次"不在模块顶层 import"这条，执行者得自己补出"那就用动态 import()"这一步语义。设计写约束时应连带给出**可行写法**，否则每次都要靠执行者的经验兜。

3. **验收步骤要标注"哪些路径复现不了"。**
   1.5-3 那个陷阱差点让验收白跑一轮（点健康面板永远不会 401）。这类"看起来该触发、其实不会"的路径，应在 TC 里显式标注，而不是留给验收人踩。
