## 遇到的坑

1. **"配置改了"不等于"生效"** —— 这是本项目踩过多次的形态（改了没生效 / 生效了没变好）。本段的处置值得保留：
   **改完顺真源链把消费者实跑一遍**，而不是只看配置文件写对了没有。它还顺手证明了"真源只有一处"
   （只改 compose 一行，两个消费者都跟着变）。
2. **拉取速率掉了一个数量级**：本次 **2.4 MB/s**（9/03 那次是 24 MB/s），1.2GB 下了十几分钟。
   影响：换模型/换大件资产的变更**必须把拉取耗时算进计划**，否则会被误判成"卡住了"。
   （本段无影响：阶段 2 不再需要联网拉模型。）
3. ★ **旧模型的 blob 会造成"假绿灯"**：`nomic-embed-text`（274MB）仍在 `ollama-models` 卷里 ⇒
   **万一将来有人把期望清单改回 nomic，检查照样 PASS**。处置：验收通过后 `ollama rm nomic-embed-text`
   （主会话已授权，并要求附删除前后的 `ollama list` 对照 + 复跑 `check-health.sh` 作证）。
   ⚠️ **不能在迁移前删**：那时跑着的还是旧 jar（nomic 口径），删了会让未完成的旧链路从"能用"变成"不能用"。
4. **陈旧容器状态会被读成新证据**：`check-env.sh` 显示 `nexus-ollama-init 已退出(0)`，那是**改动前**那次运行留下的
   容器状态，**不代表新清单跑过** —— 新证据要等下次 `up -d` 重建该容器。判据要区分"遗留状态"与"新证据"。
5. **它发现一处文档自相矛盾并上报**（按纪律没自行改）：`.claude/agents/devops-engineer/CLAUDE.md:38`
   "已执行补丁再次执行必须报错终止" 与同文件 `:129` 的订正版冲突（权威口径是 `:129`：**checksum 一致则静默跳过、
   不一致才报错终止**）。⇒ 已授权它订正自己的 charter。
6. **转义坑（第 N 次）**：经 Git Bash 调 `wsl -d X -- bash -c '…'` 时，`2>/dev/null`、`$(( ))`、`$p`
   会被 Git Bash 的参数/路径处理打乱（实测 `syntax error near unexpected token '2'`）。稳定写法：
   **脚本落盘 + `MSYS_NO_PATHCONV=1 wsl -d … -- bash /mnt/c/…/x.sh`**。已收进 `wsl.abc.md` §3.8。

## 下次怎么改进

1. **"有多个消费者的配置"改完必须跑消费者**（本次做了，建议固化为例行动作）：判据不是"文件里写对了"，
   而是"消费者打出了新值"。本项目两个真实先例（模型清单、端口真源）都是这一条。
2. **换大件资产的计划里要写"拉取耗时"**，并预留"速率可能掉一个数量级"的余量；能预拉就先预拉。
3. **清理旧资产的动作与"验收通过"绑定**：过早清理会让回归失去对照（旧链路从可用变不可用），
   过晚清理则留下"假绿灯"。本段的顺序（验收后删 + 附证据）可作为模板。
