## 做了什么

- 新建 `scripts/check-health.sh`（**585 行**），扩展 `scripts/lib/probe.sh`（474 → **641 行**，全部**追加**、无行为变更）。
- **三层判据**：

  - **L3 模型级**：`/api/tags`（`:latest` 归一化），未齐只判 WARN + 逐模型补拉命令
- **抖动免疫**：首次 503 → 5s 复采 → 复采仍 503 才 FAIL。
- **字段级审计独立成段**（§4.2.2 全表）：`data.service` 固定值、`data.status` 与 HTTP 同真同假、`data.version` **拒绝 `^@.*@$`**（报"构建层缺陷"并指向 `maven-resources-plugin`）、`data.timestamp` **不断言时区**、`checks` **键数恰好 3 且无未知键**。形态正则只在 `probe.sh` 出现**一次**，脚本只读三态结果。

## 遇到的坑

- **自己写的探针有"提前 return 导致假 FAIL"的 bug，被 stub 用例抓出**：`nexus_probe_api_health` 在 `data.version` 坏掉时提前 return，此时 `NEXUS_HEALTH_TS_OK` 为 `""`（未校验），而审计段把 `""` 当失败 → 打印 `data.timestamp = '' 不是 ISO-8601` 的**假 FAIL**。改为三态判定（`""` → "未校验，探针已在更前的字段返回"）。**这条若没跑 stub 用例，会一路带到验收现场。**
- **"已知良性异常"必须做成可证伪的两段式**：`nexus-frontend` 恒 `unhealthy`（IPv6/IPv4 假故障）是**必然会看到**的现象。处理方式是：2/6 段只记 `[WARN] 疑似已知假故障`、**延后判定、不重复计数**；6/6 段给出结论 + **三条闭合证据**（容器内对照实验 / healthcheck 报错原文 / 宿主功能探活）。**且判据可证伪**：功能探活任一不过 → 升级为 `[FAIL] 这次不是假故障`。
  - 值得记的一点：**证据③ `[::1] → exit=1` 是 agent 自己补的**，理由是"没有它，'localhost 失败'还能有别的解释，证据链不闭合"。**证据链的完整性标准是"排除其他解释"，不是"列出几条支持证据"。**
- **探针命名偏差的处置**：实现用了 `nexus_container_status` / `nexus_oneshot_state` 等，与任务规格的 `probe_*` 名不同。**选择保留现名**，理由：改名需同步改 `up.sh`/`check-env.sh` **两处已交付脚本**，行为收益为零，却会让**已评审的文件重新变成未评审**；且规格名装不下实际语义（`nexus_oneshot_state` 要给"没跑过/正在跑/已退出"三态 —— `probe_ollama_init_exit` 只给退出码，**分不出"还没跑"这个正常状态**）。改为在 `probe.sh` 头注释加"规格名 ↔ 实现名"对照表，**不留暗偏差**。
- **无状态变更约束下的验证手段**：agent 被禁止做任何改变状态的 docker 操作，于是**自建测试替身**（假 `.env`、`docker` stub、两个 python stub server）来覆盖 503 / 异常分支。这是合规且有效的做法 —— **约束不该成为不验证的借口**。
- **墙钟 21 分钟 ≠ 成本高**：`tool_uses` 70 / 18.3 万 token，与其它任务同量级；`duration_ms` 混入了等待用户输入的空闲时间。

## 下次怎么改进

- **"假 FAIL"是本项目反复出现的失败模式，应作为编码时的固定自检项**：任何"字段缺失/未校验/空值"都必须区分**"确实坏了"**与**"根本没走到这一步"**。本次即 `""`（未校验）被当成失败。**三态（通过/失败/未校验）优先于二态（通过与失败）。**
- **对"已知良性异常"固化两段式处理**：先延后、不计数 → 再由独立的功能判据给结论，**且判据必须可证伪**（能区分"良性"与"真故障"）。直接判 WARN 会掩盖真故障，直接判 FAIL 会制造恐慌。
- **写证据链要问"这些证据能否排除其他解释"**，而不是"能否支持我的结论"。本次补 `[::1]` 那条正是这个标准。
- **被测系统不可用时，写测试替身而不是放弃验证**：stub 用例本次直接抓出一个会带到现场的 bug，投入产出比极高。**"约束不允许操作"与"无法验证"是两回事。**
- **重命名类重构要算"评审状态"这笔账**：已评审通过的产物，改名会让它重新处于未评审状态，而收益常常为零。**用对照表消解偏差，比用改名消除偏差更划算** —— 前提是偏差被显式记录、不留暗处。
