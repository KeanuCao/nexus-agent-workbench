# builder 容器执行环境事实挖掘

- **Agent**：Explore（只读探索，非 devops-engineer） ｜ **耗时**：约 3 分钟 ｜ **task-id**：a166c05c4ba52877a

## 做了什么

为判断「db-patch 迁移入口在 builder 容器内能做什么」，只读搜集 nexus-builder 的全部已记录事实，覆盖 `docker-compose/{builder,backend,frontend}/`、`scripts/` 四个脚本、`docs/design/00`、`docs/agent-log/` 全部历史、`README.md`、`wsl.abc.md`、`.claude/agents/devops-engineer/`。结论要点：

1. builder 镜像**已装且构建期自证**：mvn 3.9 / JDK17 / git / node20 / psql / curl（`RUN mvn -version && node -v && npm -v && psql --version && git --version` 串联，任一缺失即构建失败）。
2. builder 服务**没有 volumes / environment / ports / healthcheck / depends_on** → 容器内既看不到仓库源码，也看不到 `/db-patch`；`WORKDIR /workspace` 是空目录。
3. builder **没有 `.dockerignore`**，构建上下文里只有 `Dockerfile` 与 `settings.xml` 两个文件。
4. Maven 走 `COPY settings.xml /root/.m2/settings.xml` 注入阿里云源；已知头号陷阱是 **cache mount 覆盖式挂载会遮蔽同路径镜像层内容**（`backend/Dockerfile` 因此把 target 写成 `/root/.m2/repository`）。
5. `check-env.sh` 有一份**本地镜像白名单** `LOCAL_IMAGES="nexus-builder:dev nexus-backend:dev nexus-frontend:dev"`，用于豁免镜像前缀检查——新增本地镜像忘了登记会报 FAIL。

## 遇到的坑

1. **builder 镜像的 ENTRYPOINT/CMD 全仓库无留档。**
   现象：`up.sh:131` 的 `compose run --rm -T builder "$DB_PATCH_CMD"` 依赖「命令名可解析」，但没有任何记录说明基础镜像 `maven:3.9-eclipse-temurin-17` 的 entrypoint 会不会把它吃掉。
   处理：如实标注为**推断**（基础 maven 镜像带 `docker-entrypoint.sh`，结尾 `exec "$@"`），不写成结论。

2. **`psql` 版本是推断值。**
   现象：`builder/Dockerfile:33` 的注释写「apt 装到的是 v14 客户端」，但仓库无 `psql --version` 实测输出。
   处理：标注为推断，落地时实测回填。

3. **发现设计文档的文字漂移。**
   现象：`docs/design/00-环境与部署.md:114-115` 写「BuildKit cache mount 将 `/root/.m2` 与 `node_modules` 缓存分开持久化」，是**落地前的旧写法**；实际落地为 `/root/.m2/repository` 与 `/root/.npm`。
   处理：记入待订正清单，未自行改动文档。

4. **构建期自证的输出没有留档。**
   现象：`RUN mvn -version && node -v && …` 的输出只在构建日志里，一次性、不落盘，导致「容器里到底装的什么版本」只能靠推断。
   处理：列为改进点（见下）。

## 下次怎么改进

1. **让构建期自证的输出落盘到仓库**：把 `RUN mvn -version && node -v && psql --version …` 的输出 tee 到一个随镜像版本化的文件（或写进 `wsl.abc.md` 的实测记录表），此后「容器内有什么版本」是**查得到**而不是**推得出来**。
2. **凡「容器内某工具有没有」的判据，一律标注「待实测」并附一条可直接粘贴的实测命令** —— 本次 ENTRYPOINT 与 psql 版本两条都是靠推断过关的，而推断正是本项目已经出过事故的地方（`:latest` 归一化、`ollama list` 退出码恒 0）。
3. **镜像定义与设计文档同批更新**：`/root/.m2` → `/root/.m2/repository` 这类漂移，根因是改 Dockerfile 时没回改设计文档。改镜像定义时应同步 grep 设计文档里的同一路径。
