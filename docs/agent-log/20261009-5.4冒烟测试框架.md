## 遇到的坑

1. ★ **缺口是"默认值掩盖"型的静默缺口**：`application.yml` 把 `answer-model-type` 默认成 `DEEPSEEK`，
   所以"测试档少配一个键"这件事**在拉起环境时不报错**，只有真跑到 ask 那一步才以 20100 现形 ——
   而 20100 又容易被误读成"密钥/网络问题"。处置：静态核实 + SKIP 文案写明区分口径 + 上报修法；
   主会话复核时**补扫 `.env.local` 键名全集**，确认这是唯一缺口（没有第二处同类）。
2. **产物目录形态与任务书"建议三子目录"不一致**：pytest-playwright 内建把 trace 与失败截图同落
   `artifacts/playwright/<用例目录>/`，agent 给了理由（自建"分离器"=多一处机械动作、零收益）且**没有硬改**。
   主会话采纳 —— 教训：任务书里的"建议形态"要标注「工具内建形态优先，除非有明确理由」。
3. **运行产物会污染"跑前跑后 `git status` 一致"这条验收判据** ⇒ agent 在 `qa/e2e/artifacts/` 内部
   自建 `.gitignore`（红线不许改根 `.gitignore`）——**目录内自洽**的处置留作惯例。
4. **`.venv` 的忽略不需要动根 `.gitignore`**：实测 `python -m venv` 自带 `.venv/.gitignore`（内容 `*`）
   已覆盖（`git check-ignore -v` 命中）——原以为要加一行，实测为零改动。
