## 遇到的坑

1. **派活时给的前提是过期的**：任务说明里写「当前分支 `<revision>` = `0.2.1`」，它实测是 **`0.2.2`**（用户已把 main 合进分支）。
   → 处理：它**当场测出来并上报**，没有照着错前提写文档。而且这次「抄前提就会抄错」正好是任务本身要消灭的那类问题 —— 口径本就是「不写死、跟随真源」，所以不影响改法。
2. **「保留字面量」与「不写死」的张力**：`README.md:112` 那句写死 jar 文件名的全部意义是「**PowerShell 不展开通配符**」，直接换成通配会让那句话自相矛盾。
   → 处理：改成 `<版本号>` 占位 + 指明真源取值方式 —— 既去掉了数字，又保住了那条提示。这是需要判断的例外，处理得对。
3. **历史记录不能碰**：`docs/agent-log/*`、`docs/task/task.1+环境准备.md` 的历史实测值、`docs/drafts/*` 的快照里也有 `0.2.0/0.2.1`，但它们是**当时事实的记录**。
   → 处理：不改写，只在报告里逐条说明为什么留着。

## 下次怎么改进

1. **派活时凡涉及「当前值」的前提，一律写成「用这条命令取，别信我给的数字」** —— 本次就是活教材：我给的值过期了，执行者若照抄，交付物里就会多一条新的错话。这条对「值会漂移」的场景（版本号、端口、提交号）普遍适用。
2. **文档清理类任务的标准收尾固定为两项**：① 附一条全仓库 grep 的**原始输出**；② 对每条残留**逐条归因**（保留的也要说清为什么）。本次这么做让复核成本降了一大截 —— 建议写进此类任务的分派模板。
3. 对「示例需要可读」与「不许写死」冲突的地方，**默认选「保留值 + 就地标注非真源」**，而不是删掉值或改成占位符 —— 除非那句话的语义依赖具体形态（如 PowerShell 通配那条）。
