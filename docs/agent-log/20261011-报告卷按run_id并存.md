## 做了什么

1. **发布语义：整树替换 → 按 run_id 并存**。`finalize-run.py` 的 `publish()` 只替换 `runs/<run_id>/`，
   其它 run 目录一律不碰；卷根刷新两样 —— 索引页 `index.html`（扫描 `runs/*/run-results.json` 生成、
   最新在前）与 `run-results.json`（最新一次）。历史失败留痕（trace/截图）由此不再被下一次覆盖
   （修掉了"库里 `trace_path` 指向已被覆盖文件"的老边界）。
2. **索引页与每次运行的落地页分家**：`render_index_page`（卷根）+ `render_run_page`（`runs/<id>/`）；
   重放旧 run 不顶掉"最新一次"、不产生重复条目（按 `(started_at, run_id)` 倒序 + 按 run_id 去重）。
3. **自愈式首清（用户拍板）**：卷根没有 `runs/`（全新卷）**或** `runs/` 下没有任何子目录（旧布局）
   ⇒ 整树清空一次 ⇒ **首跑新脚本即自动迁到新布局**；此后永不再整树清（否则会毁掉历史 run）。
4. **端口真源单一化**：新增共享模块 `scripts/py/report_env.py`（读 `docker-compose/.env.test` 的
   `REPORT_PORT`），三个消费方 import —— finalize-run / notify-mail / **workflow 步骤 6 的 Step Summary**。
5. **邮件带报告地址**：`notify-mail.py` 正文新增「报告」块（索引 / 本次运行页 / Allure 直链），host 取
   `REPORT_BASE_URL`（默认 `http://localhost:<REPORT_PORT>`）；`E2E_RUN_ID` 由必填改可选并全路径降级（不崩）。
6. **Step Summary 给本次直链**；`RUN_ID_PATTERN` 拒掉 `.` / `..`。

## 遇到的坑

1. ★ **"覆盖"与"并存"是两种发布语义，切换时必须连带回答"陈旧数据怎么办"**：原实现整树替换（简单、不留脏），
   改成按 run 并存后，卷里已有的**旧布局**文件成了没人负责的残留 —— 旧 URL `/allure-report/` 会继续指向
   **上一次的报告**（而不是 404）。处置：自愈式首清判据 + 迁移代价写进设计 §7.4.7-3。
2. ★ **迁移的固有代价要提前说清**：首清会把旧布局里**上一次运行的卷内内容一并清掉**（该次运行的 DB 行与
   Metabase 看板不受影响）。若不接受，得把旧根内容按 `runs/<旧 run_id>/` 归位 —— 属新逻辑，本次未做。
3. **"卷根没有 `runs/` = 全新卷"这个判据对旧布局不成立**：真卷里 `runs/` 是**存在的**（里面是平铺
   `<run_id>.json` 文件）⇒ 判据必须细到"有没有**子目录**"。实现用 shell 通配 `/dst/runs/*/`（尾斜杠只匹配
   目录、空目录不展开），不依赖 busybox 的 `-quit`。
4. **端口字面量会顺着"顺手加的一行"扩散**：`[PASS]` 提示行、Step Summary 里都写死了 `12008`。处置：抽
   `report_env.py` 一份读法（notify-mail 走 `try/except` 降级、finalize-run 裸 import —— 它本就依赖仓库布局）。
5. **测试方法学两个同族坑**：① `$?` 经 Git Bash → `wsl … bash -c` 的 argv 层会被打乱（`false; echo $?` 显示 0）
   ⇒ 退出码要用 `bash -s` 喂 stdin / 落盘执行；② `cat 文件 | wsl … bash -s <<'EOS'` 两条 stdin 争抢 ⇒
   脚本被吃光、零输出。**远程脚本不要与管道混用 stdin。**
