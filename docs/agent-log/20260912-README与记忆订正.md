  - 全 lock 中唯一引用处是 rollup 的 `optionalDependencies`；
  - rollup 4.63.1 的运行时产物 `dist/rollup.js` / `native.js` / `shared/index.js` **零引用** `@napi-rs/lzma`；rollup 自身 `package.json` 的 `comments` 字段自述该条目服务于其**交叉编译工具链**（`napi build --use-napi-cross`, #6461）。

  结论不变（不构成风险），但**兜底理由换成了可复现的证据**。
  - **这是本次会话第二次同类事故**（上一次是 `wsl.abc.md` 的 0.3.4"未开工"）。两次都是**主会话转述时未核实**。转述链条上的每一环都在给错误增加"权威感"。

- **记忆过期问题的根因反思（agent 自己给出，质量很高）**：
  1. **把"状态"混进了"证据"里** —— 证据（容器内 `localhost` 解析到 `::1`、`awk` 整行比必然不等的机制）**不随时间变化**，而"两条都还没修"是**状态**，只在写下那一刻为真。两者同行同语气，**状态被证据的权威性"背书"了**。
  2. **越是证据充分的状态陈述越危险** —— 后来人会判定"这条已实测过，不必复核"。**过期信息披着最像证据的外衣。** agent 自陈：复核时 compose 里 `127.0.0.1` 已在，与记忆直接冲突，**"如果我按记忆行事，就会去修一个已修好的东西"**。
  3. **记忆没有"有效期"这一维度。**

- **实测补强（未用在线文档，符合本项目铁律）**：npm `engine-strict` 语义最小复现 —— 默认 `npm install --dry-run` → `npm warn EBADENGINE` **exit 0**；`--engine-strict=true` → `npm error notsup` **exit 1**（npm 11.13.0 实测）。
- **未闭合项已如实标注**：容器内 `npm ci` 的实际日志未留档（Node 20 自带 npm 10.x ≠ 复现用 11.13.0），完全闭合需下次构建日志确认无 error 级 EBADENGINE。
