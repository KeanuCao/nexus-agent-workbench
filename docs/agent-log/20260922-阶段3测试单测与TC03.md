## 遇到的坑

1. ★ **走 nginx 的上传被 1MB 体量墙挡住（产品缺陷，阻塞阶段验收）**。
   现象：900,000 字节走 8088 → 401（到后端了）；**1,682,689 字节（= 阶段验收夹具）→ HTTP 413 +
   nginx 的 HTML 错误页**；同样大小直连 8089 → 401（后端一切正常）。
   原因：`docker-compose/frontend/nginx.conf` **没配 `client_max_body_size`**，nginx 默认 **1m**；
   而后端与契约都声明 10MB ⇒ **前端链路比后端更早拒**，且 413 的响应体**不是 `Result`**
   （前端拦截器只会报"响应体不是统一的 Result 结构"，把排查方向带向"接口写错了"）。
   处理（主会话）：加 `client_max_body_size 12m;`（与后端 `max-request-size` 对齐）+ **重建前端镜像**
   （`nginx.conf` 是 COPY 进镜像的）→ 复测 1.68MB 走 8088 得 **401 + 标准 `Result`** ✅。
   **教训**：又一处"**只有走 nginx 才现形**"的坑（与阶段2 的 `proxy_buffering` 同类）——
   凡"前端链路 vs 直连后端"会分叉的配置（缓冲、超时、体量、编码），都必须在**前端那条链路**上验。
2. **Python 改文本又翻出行尾**（本阶段第 2 次）：3 个文件被写成 CRLF，脚本报
   `$'\r': command not found`。已转回 LF 并复验（javac exit 0 + 59/59 绿 + 脚本干跑 0）。
   **同一坑两次 ⇒ 应固化成纪律**：脚本改文本一律 `newline=""` 或走二进制。
3. **撞 100 轮上限、产物已落盘但没交回报**。现象：轮次耗尽时脚本/测试/TC 都写完了，却一个字的回报都没有
   ⇒ 主会话只能靠 `git status` 反推它做了什么。教训：**长任务要分段交付**（写完一组就回报一次），
   或在接近上限前主动收尾。
4. **测试自己写错了两处**（已修，不是产品缺陷）：① 把"每块长度 > overlap"当无条件不变量 ——
   单块短文本（设计 §4.4 规则 4）合法地短于 overlap，已加豁免；② `answer-model-type` 的**空串**与
   **未知取值**走两条不同出口（`SystemException`/500 vs `BusinessException(10200)`/200），
   测试最初按一条写。后者作为"已知噪音"记进 TC-03 §10，未改产品。
5. **脚本自己的缺陷：跑前指纹取在登录之前**（必然 401、指纹无意义）—— 靠"干跑"抓到。
6. **测试类的包名必须与生产类一致**：`TextChunker.chunk` / `TikaDocumentParser.normalize` 是**包内可见**
   的测试缝，测试类丢在 `...rag` 下会编不过（设计 §7.1 已写明）。
7. **宿主 `javac` 默认 GBK**：不加 `-encoding UTF-8` 就对中文源码报 unmappable character。

## 下次怎么改进

1. **把"无 mvn 的本地编译/跑测路线"固化成脚本**（jar 缓存 + junit-console-standalone + mockito +
   `javac @argfile` + `java -jar … execute`）：本段已写进 agent-memory（`local-test-compile-route.md`），
   下一步应该落成 `qa/scripts/` 下一个可复用脚本，而不是每次重拼命令。
2. **脚本一律先"干跑"**：拿一个已知不存在的接口/库跑一遍管路，能抓到"指纹取早了""变量没赋值"这类
   只有真跑才暴露的自身缺陷（本段抓到一条）。
3. **"前端链路 vs 直连后端"的差异要列成一张检查表**（缓冲 / 超时 / 体量 / 编码 / 头），
   每次动 nginx 或加新接口就过一遍 —— 本阶段的 413 与阶段2 的 `proxy_buffering` 是同一类，
   第三次出现时应该已经有一张表。
4. **长任务分段交付**：产物落盘不等于交付，回报才是（撞上限那次差点让主会话按 `git status` 猜）。
