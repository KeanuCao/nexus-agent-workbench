## 遇到的坑

1. **⚠️ 设计文档内部端口自相矛盾：§3.5 的 curl 写 `localhost:8080`，而 §6.5 自己写「直连 8089 也正常」，真实值是 `.env` 的 `BACKEND_PORT=8089`。**
   验收判据 2.3-1 就挂在这条命令上，照抄直接 `Connection refused`。
   → 处理：**按纪律上报，未自行挑一条改**，并明确写「同一份文档两个端口 = 文档内部矛盾，必须报到你这里而不是我自己挑一个改」。主会话复核后确认属实。
2. **`fetch` 漏头的坑属"照做必踩、但文档完全没提"**：设计只说 `Authorization` 不生效，漏了 axios 同时注入的 `Content-Type: application/json`（`request.ts:60-62`）。`fetch` 未显式给头时会自动打 `text/plain`，而后端按宪法声明了 `consumes=application/json` → **第一条请求就 415**，且响应体不是 `Result`，会把排查方向带偏成"网关/代理问题"。根因是 `frontend/src` 全目录**零 `fetch(` 调用**，没有现成封装可继承这套默认头。
3. **中文会被静默切乱 —— 且原设计的应对不够。** §9 风险 4 的"按行缓冲累积、只处理完整行"解决的是**行**被切断，而前端真正的杀手是**字符**被切断：`reader.read()` 返回 `Uint8Array`，`TextDecoder` 少了 `{stream:true}` 时，一个汉字被 TCP 分片劈成两半会解成 U+FFFD **且不抛异常**。
   关键判断：该风险条目对**后端**（NDJSON 按行）够用、对**前端不够** —— 因为**前端的缓冲单位是字节串而不是字符串**。叠加本项目 delta 是"你""好"级别单字帧、帧数上千，分片边界撞在汉字中间是必然而非偶然。
4. **设计里两处"复用既有实现"实际不成立 —— 因为那些内部没有导出。** §5.1 要求 401 处置"与 `request.ts` 一致、复用同一套登出函数"，但 `handleUnauthorized`（`request.ts:158`）、防抖标志 `redirectingToLogin`（`request.ts:156`）、`isResult`（`request.ts:70`）**全是模块私有**；而 §5 的改动清单里**没有 `request.ts`**。不改它就无法复用，"复用"是纸面上的。
   附带风险：防抖标志必须跟着函数一起搬走，否则"单例防抖"是假的 —— 两个互不可见的标志会让一次 401 风暴连续 push 两次 `/login`，正是该条想避免的"两套登出行为"。
5. **§3.3 与 §4.2 对 `20100` 的载体自相矛盾**：§3.3 开篇断言「`SseEmitter` 返回的那一刻响应头已发出」（⇒ 只能走 `event: error` 帧，表里那行 503 永不出现），而 §4.2 时序图把上游调用与降级重试画在 emitter 交给前端**之前**。两者只能成立一个，而前端可见行为完全不同。这条不是纸面问题：§6.4 描述的"密钥为空 → 选云端 → `20100`"是被测场景，若只按表格实现 503 分支，"没密钥"会显示成一个空白气泡。

## 下次怎么改进

1. **设计文档里凡是环境相关的字面量（端口、路径、URL），落笔时就该从唯一真源取值**（`.env` / `nginx.conf`），不要手写。
   本次 8080 vs 8089 是**同一份文档内部**的矛盾 —— 这类矛盾自查最难，因为两处都"看着对"。判据：写完含字面量的命令后，grep 一遍该值在全文出现几次、是否一致。
2. **派评审时把"契约文档是否已落地"当作前置门禁先问一句。** 本次前端同事的第一条结论就是"不能开工"，而这个判断只花了一次 grep —— 但它决定了后面所有条目的意义。同理：设计说"本节是某文档的摘要"时，摘要与真源是否同步必须核实。
3. **前端接流式接口，"axios 帮你做了 / `fetch` 不做"应列成固定清单逐条打勾**：`Authorization`、`Content-Type`、非 2xx 不抛错（要自己判 `response.ok`）、`Content-Type` 判定要 `includes` 而非全等（Spring 会带 `;charset=UTF-8`）。这类坑的共同特征是**症状会指向错误的方向**（415 看着像网关问题、乱码看着像编码配置问题）。
4. **`TextDecoder` 的 `{stream: true}` 应进项目的流式解析模板**，连同"EOF 也要 `decoder.decode()` 收尾一次"。判据：任何按字节读流再解码的地方，缺这个参数就是 bug —— 且它在纯中文/纯英文语料下**测不出来**，只在多字节字符被分片时暴露。
5. **声称"复用既有 X"时，先确认 X 导出了没有。** 没导出 ⇒ 宿主文件必须列进改动清单，否则实现者只能抄一份，而"抄一份"恰恰会让原本要消除的重复以更隐蔽的形式回来（如本例的防抖标志）。派活时把这条写进要求，可以让实现者少走一个来回。
