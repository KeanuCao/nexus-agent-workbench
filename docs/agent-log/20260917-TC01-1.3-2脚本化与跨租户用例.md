## 做了什么

1. **复核主会话的发现并精确化边界**：确认「1.3-2 的预期有一半没被步骤覆盖」成立 —— `/api/auth/me` 无入参（`AuthController.java:84-87`），`userId`/`tenantId` 全部取自 `TenantContext`（`AuthServiceImpl.java:143-165`），而上下文由过滤器从 token claim 原样写入（`JwtAuthenticationFilter.java:158`）。故两次调用的返回值就是各自 token 的 claim，**租户条件完全失效时也一字不差**。
   边界精确化：这个 case 抓的**不是「够不到」**，而是**「上下文取到了错值」**（ThreadLocal 串租户 / tenantId 绑成常量或别人的值）—— 因为 `t_user` 的查询确实会带 `tenant_id`（`MybatisPlusConfig` 注册了 `TenantLineInnerInterceptor`，且 `t_user` 不在结构性豁免表内）。
2. **`qa/scripts/tc01-two-tenant-me.sh`**（块 1）：真登录 `admin`/`demo` → 各调一次 `/me` → 两条响应体**原样并排打印**（含 HTTP 码、登录返回的 `data.user`、`/me` 的 `data`、本地解码的 token 载荷）→ 字段对照表 → 登出 → 指纹。**脚本只打印观察、不打 PASS/FAIL**。
3. **`qa/scripts/tc01-cross-tenant-token.sh`**（块 2）：真登录 → **先验签真 token** → 本地重签两份（逐字节沿用 header，沿用 `jti`/`sub`/`iat`/`exp`，**只换 `tenantId`**）→ 两个方向各调一次 `/me`。期望 **401**；若 200 则是「A 租户的 username/userId + B 租户的 tenantId/tenantCode」的**混合身份** ⇒ 跨租户泄漏。
4. **`docs/test-cases/TC-01.md`**（块 3）：1.3-2 步骤换脚本、预期改写成步骤真能证明的三件事 + 新增「1.3-2 备注」写明**本条证明不了什么**；新增 **TC-01-1.3-5** + 备注；1.3-4 加交叉引用；编号对照补 `1.3-5`；前置条件加 Redis 指纹行；「fail-closed 的实际触发」行做范围订正。
5. **上报一处文档矛盾**（未改文档）：`design/01` §9 的 1.3-2 写「用租户 A 的 token **查用户列表**」，而同一份设计 §11 明说「`/api/auth/me` 之外的任何用户管理接口本轮不做」，`task.2` 原文只有「两个租户的数据互不可见」—— 三条不能同时成立。TC-01-1.3-2 那句含糊的预期正是这个矛盾的沉淀物。按更忠实的一条（task 原文 + `docs/api/README.md` §5.4 末句的承诺）先做。

## 遇到的坑

1. **⚠️ 主会话的交接里有一个洞，会让用例「伪装成 PASS」（本次最重要的坑）。**
   `40101` 是**「隔离生效」与「签名错」共用的码**。主会话给的推演只验证了"隔离生效 → 401 → 40101"，**没注意"密钥不一致 → 验签失败 → 同样 401 + 40101"**。而"后端生效密钥是否等于 dev 默认值"本来就只是个读配置得出的假设（compose 未注入 `NEXUS_JWT_SECRET`）—— 两者叠加，**密钥配错时这条用例会假通过**。
   → 处理：脚本在**动任何请求之前**先用本地密钥**验签一份真 token**；验不过 → **退出码 3、明确"不给结论"**。顺带把那个假设从"信任基础"变成了**运行期自证**。
   → 教训的形状：**设计"期望某个错误码"的用例时，先查这个码有几个来源。**
2. **bash 在未被 trap 的信号下根本不跑 EXIT trap。**
   第一稿的注释写了「Ctrl-C 也会清理白名单键」—— **这是错的承诺**（写的时候以为 EXIT trap 会兜住）。干跑实测发现 SIGINT/SIGTERM 下 trap 不执行。
   → 处理：显式 `trap 'exit 130' INT` / `trap 'exit 143' TERM`，把信号转成一次正常退出，让 EXIT trap 真正生效；并在注释里写清前提（**前台运行**）与最坏残留。
3. **干跑还抓出一个：`curl -o` 连不上时不建文件 → `cat` 被 `set -e` 吞成退出码 1。**
   表现为「后端不可达」时的退出码与设计不符（应为 3，实际 1）。已修。
4. **无害性自证不能用键数，要用差异。**
   用户环境里**跑前就有 6 个别的用例留下的白名单键** —— 只比个数会把"别的用例正常登录"误报成泄漏。
   → 处理：改取**键清单指纹 + 差异清单 + 自建 jti 的 `EXISTS`**（跑前有、跑后没有的键若非空，脚本会列出是哪几个）。
5. **WSL 内 `jq` / `node` 都不在**（实测 `MISS`；`python3` 3.12.3 / `curl` / `openssl` / `perl` / `xxd` / `base64` / `wget` / `docker` 均在）。JSON 取值改走 python3 点分路径 helper。
6. **从 Git Bash 调 WSL 时 `MSYS_NO_PATHCONV=1`**（前一天记过的坑，本次再次踩到）。

## 下次怎么改进

1. **凡用例的判据是"某个错误码"，落笔前先 grep 这个码有几个产生点。** 同一个码被多条路径共用时，用例会在**某一条路径**上假通过 —— 这种假通过比假失败危险得多，因为它看起来是绿的。产出：要么把前置条件变成运行期自证（如本次的验签前置），要么换一个不被共用的观察。
2. **自造 token / 自造凭据的用例，第一步永远是"用本地密钥验签一份真件"。** 这把"我假设密钥是 X"变成"我证明密钥是 X"。成本一次请求，收益是整条用例从"可能是假的 PASS"变成"真的 PASS"。
3. **写清理承诺（"Ctrl-C 也会清理"）之前，先在一个桩环境里 Ctrl-C 一次。** bash 的 EXIT trap 只覆盖正常退出与**已被 trap 的信号**；`kill -9` 永远兜不住，这个也要写进注释而不是回避。
4. **桩环境干跑值得做，且成本远低于收益**（本次抓出 2 个真 bug，且都不靠真环境就能发现）。桩要复刻**契约语义**而非实现 —— 按 `docs/api/README.md` 写，不按源码抄。
5. **"无害性自证"用差异而非计数。** 被测环境里存在**别的用例留下的状态**是常态，不是异常；指纹设计必须能区分"我写的"和"别人早就在的"。
6. **复核主会话/上游给的推理时，专门花一步问"还有没有第二条路径能产生同样的观察结果"。** 本次的洞就出在这儿：主会话推的是正向路径（隔离生效 → 401），漏了反向路径（验签失败 → 同样 401）。**同一观察的两个来源，是判据里最隐蔽的假通过来源。**
