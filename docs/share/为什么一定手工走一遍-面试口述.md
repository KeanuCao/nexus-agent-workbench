# 为什么「照着清单手工走一遍」不能省

> **这是什么**：面试口述素材（2–3 分钟）。**不是项目规范**，不需要与代码保持一致 —— 别被别的文档引用成判据。
> **但事实是真的**：每个细节都能落到具体文件与行号（见文末「底料」），被追问时接得住。
> **来历**：2026-09-17，逐条手工验收阶段1 的认证功能时，卡在「过期 token」这一条。

---

## 口述正文

### 【引子】

面试官问我：这个项目里 AI 参与了多少？

我不想给一个百分比。我说件小事吧。

### 【场景】

我在做统一认证 —— 登录发 JWT，之后每个请求过一道过滤器。功能写完，我列了一份验收清单，一条一条手工走。

走到「过期 token」这条，我卡住了。

### 【第一次撞墙】

清单上写的是：把配置里的过期时间改成 0，重签一个 token，然后调接口，期望 401。

我照着改。结果**登录直接 500，一行 token 都没拿到**。

### 【挖下去：两个错叠在一起】

查下去发现，这一条判据里叠着两个错。

**第一**，那个配置项的名字，全仓库根本不存在 —— 文档里写的和代码里绑定的不是同一个键。我 grep 了一下，**只命中文档自己那一行**。一个判据如果全仓库只命中它自己，它多半已经失效了。

**第二**，就算名字改对，取值 0 也走不通。因为 token 的有效期同时是 Redis 白名单的 TTL，代码里有一条**有意**的守卫：TTL 必须是正数，否则直接抛异常。所以 0 的后果是登录必挂，不是"拿到一个马上过期的 token"。

写这条判据的人不会知道它错了 —— **因为它从来没跑过自己写的东西**。

### 【转折：惯性解法 vs 退一步】

我当时的下意识是：那就改小一点，改成 2 秒，重建容器，登录，等 3 秒，再调。

我问了一句「这个参数怎么改」。得到的回答是：**这条用例根本不需要改环境。**

理由是过滤器的判定顺序 —— 它**先**验签名和有效期，**再**去 Redis 查白名单。所以一个本地签的、已经过期的 token，和一个真签发后等到过期的 token，在过滤器里走的是**同一条路径**。签名对、时间过了，就够了 —— `exp` 是谁写进去的，过滤器不关心。

于是这条用例从「改配置 + 重建容器 + 污染其他用例」，变成了一段**纯本地的计算**：不改任何东西，不用等，不用清理。这个思路超出了我的惯性。

### 【落点】

所以我现在的做法是：这份清单，**每一条都手工走一遍**。

因为「判据本身写错了」是个**结构性盲区** —— 单测、CI、静态检查，检查的全都是**代码**；没有人检查判据是不是指向了一个**真实存在的开关**、那个取值**是不是走得通**。只有真跑一遍会撞上。

（停一下）

**而且我是先卡住了，才去问的。要是没跑，我连自己有一条坏判据都不知道。**

## 怎么用

**入口**：这个故事可以从好几种问法切进去，不必等"AI 参与多少"——

- 「你平时怎么保证质量？」→ 直接讲，落点在最后的"结构性盲区"
- 「AI 写的代码你放心吗？」→ 先给结论：**代码我能审，判据没人审** —— 然后讲故事
- 「讲一个你排查问题的例子」→ 从【第一次撞墙】进，前面引子可省

**时长**：全文约 750 字，正常语速 2 分半。面试官打断就停在【落点】第一段，那句是钩子。

**⭐ 关于诚实**：被追问「那这个不用改环境的思路是谁想出来的」—— **如实说是问 AI 助手得到的**，不要含糊成自己想出来的。这个故事的价值恰恰在于**人机各出一半**：我负责**真跑**（所以撞见了缺陷），它负责**给方案**（所以跳出了我的惯性）。人机协作里，"人"不可替代的那一半是**执行与验收**，不是想点子。这么答比"我自己想到的"更站得住，也更像已经在用 AI 干活的人。

## 追问预案（大概率会来）

| 追问 | 怎么接 |
|---|---|
| 「所以你不信任 AI 写的代码？」 | 反了 —— 代码我审得动，能看。**没人审的是判据**：判据不是代码，进不了 CI。这就是盲区的来源。 |
| 「这条用例为什么不用自动化测？」 | 自动化只会**忠实地执行一个错判据** —— E2E 脚本按错的键名去改配置，照样卡在同一处。**自动化能验代码，不能验"判据是否描述了真实世界"。** |
| 「过滤器为什么先验有效期、再查 Redis？」 | 顺序是有意的：过期 = "重新登录即可"，白名单没有 = "这个 token 不该存在了（已登出）"，两者要给前端**不同的处置码**，所以必须先分清。也正因为顺序固定，"过期"这条的判据才能**脱离 Redis 独立成立**。 |
| 「那你怎么知道新写法是对的？」 | 我独立复算了一遍签名，并断言 `exp - iat` 等于配置的有效期 —— **夹具自己也要有判据**。 |
| 「0 不行，那配成负数呢？」 | 同一条守卫拦掉，一样是登录 500。守卫是 `<= 0`，不是 `== 0`。 |

## 底料（被深挖时的事实清单）

| 事实 | 落点 |
|---|---|
| 配置项名字不存在 | 文档写 `nexus.jwt.expire-minutes`；代码绑定 `nexus.jwt.expire-seconds` |
| 取值 0 会让登录必挂 | TTL 正数守卫 → `SystemException` → HTTP 500 + `code=50000` +「系统繁忙，请稍后重试」 |
| 守卫是有意的，不是缺陷 | 有效期同时是 Redis 白名单的 TTL，两者必须一致；非法 TTL 就该在登录时炸 |
| 判定顺序 | 过滤器：① 无 token → 40100；② 解析（签名 + 有效期）→ 过期 40102 / 非法 40101；③ Redis 白名单不中 → 40101 |
| 关键推理 | ② 在 ③ 之前 ⇒ 本地签的过期 token 与真过期 token 同路径 ⇒ 不需要先登录、不需要碰 Redis |
| 新写法 | 一段本地 HMAC 计算（python3 标准库）：零写操作、零等待、零清理 |
