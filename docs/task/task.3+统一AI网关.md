## 子任务拆解

### 2.1 模型服务抽象与实现
- **输入**：task.2 的 1.1
- **输出**：`AiModelService` 接口 + `OllamaService` + `DeepSeekService` 实现（Spring AI 或 OkHttp + 策略模式）
- **依赖**：1.1
- **验收标准**：两个实现各自可独立完成对话；调用大模型的关键流程有 `log.info` 链路日志

### 2.2 工厂模式动态切换
- **输入**：2.1
- **输出**：`AiModelFactory`，按前端传入的 `modelType` 返回对应实现
- **依赖**：2.1
- **验收标准**：传 OLLAMA / DEEPSEEK 分别命中对应实现；未知类型抛业务异常

### 2.3 SSE 流式输出接口
- **输入**：2.2
- **输出**：`/api/chat/stream`（SseEmitter，不用 WebSocket）
- **依赖**：2.2
- **验收标准**：curl 可见增量分片而非一次性返回；客户端中断时 SSE 资源正确释放

### 2.4 前端对话页
- **输入**：task.2 的 1.5
- **输出**：对话页：模型下拉（本地Qwen / 云端DeepSeek）+ fetch 流式读取 + 打字机渲染
- **依赖**：2.3
- **验收标准**：下拉切换模型，实时打字机输出

## 🚩 阶段交付物
`/api/chat/stream` 接口 + 前端对话页

## ✅ 阶段验收标准
选择"本地Qwen"走 Ollama、选择"云端DeepSeek"走 DeepSeek，均能实时打字机输出
