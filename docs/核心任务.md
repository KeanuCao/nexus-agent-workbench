### 测试案例约定（每个阶段强制）
- 每个阶段性任务完成后，**必须**在 `docs/test-cases/` 下生成对应测试案例（TC-00 对应阶段0，依此类推）。
- 测试案例需与功能演进同步维护：功能变更时更新对应 TC 文件，新增功能时新增 TC，保持编号与阶段对应。
- **步骤列必须可被另一个人无损复现（2026-09-15 新增，硬要求）**：
  - **命令类用例**：每一格是**能直接复制粘贴执行的完整命令**，自带必需的前置（`cd <目录>`、环境变量）。禁止速记 —— 如 `exec builder db-patch-migrate`（省掉了 `docker compose`）、`跑迁移`、`改 pom 的 <version>`。
  - **操作类用例**（前端交互、手工造场景）不适用「一条命令」，但要写成**逐步编号动作**：点哪个按钮、输入什么、每步立刻能看到什么。同样禁止压缩 —— 「清空 localStorage → 访问 `/dashboard`」这种写法让人无法复现（在哪清、清完刷新没有）。
  - **一律禁止**把多步压成一行箭头串（`改 pom → push → exec builder git-sync`）：多步就分行/分条。
  - **判据**：照着这一格走一遍，不需要任何补充信息、不需要任何自行翻译。
  - **来历**（为什么升级成硬要求）：TC-00-0.1-7 的步骤写成速记，执行者照着敲不出来、只能自行翻译成 `docker exec nexus-builder git-sync`，导致该用例的失败**无法归因**——分不清是产品缺陷、文档缺陷还是执行偏差。测试案例的全部价值在于「可被另一个人无损复现」，速记会直接摧毁这一点。
- **人工逐条执行不是走过场（2026-09-17 新增）**：判据**自身**的缺陷（配置键名不存在、取值根本走不通）静态复核、单测、CI 全都照不到，只有「照着这一格真跑一遍」会撞上。实况见 `.claude/agents/qa-engineer/CLAUDE.md` §5.3（人手工执行抓到判据缺陷；而正确的修法是「这条用例根本不用改环境」，不是「把参数改对」）。
- **步骤需要手工拼装多步命令的，落成脚本（2026-09-17 新增，硬要求）**：凡步骤需要执行者手工拼装 ≥2 条命令、或要把上一条的输出喂给下一条（如「登录拿 token → 带着它调下一个接口」），应落 `qa/scripts/` 的一个脚本；步骤栏只留一行可复制粘贴的命令 + 一句「这一步在干什么」，**脚本只做机械动作、不打 PASS/FAIL**（**纪律全文见 `.claude/agents/qa-engineer/CLAUDE.md` 的编写纪律 §1 —— 本处只留摘要，冲突时以 charter 为准**）。来历：用户走 TC-01-1.3-2 时提出「我得自己拼命令，这不是人擅长的事」。
