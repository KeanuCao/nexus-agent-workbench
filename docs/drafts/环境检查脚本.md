你说得对，应该先把"每个容器要检查什么"梳理清楚，再落到脚本里。这样脚本才有明确的验收标准，面试时也能讲清楚"我为什么这么设计健康检查"。

下面是我梳理的 **5 个容器的检查点清单**，按"基础 → 业务 → 深度"三层递进：

---

## 📋 容器检查点清单

### 1️⃣ `nexus-postgres` (PostgreSQL 16 + pgvector)

| 层级 | 检查点 | 检查方式 |
|---|---|---|
| 基础 | 容器状态 `running / healthy` | `docker inspect` |
| 基础 | 5432 端口可达 | `docker exec pg_isready` |
| 业务 | 能用配置账号密码登录 | `docker exec psql -c "SELECT 1"` |
| 业务 | **pgvector 扩展已安装**（RAG 核心依赖） | `SELECT extname FROM pg_extension WHERE extname='vector'` |
| 深度 | db-patch 补丁是否全部执行（`t_db_patch` 表记录数） | 查补丁记录表 |
| 深度 | 多租户表 `tenant_id` 字段是否存在 | 抽查业务表 schema |

### 2️⃣ `nexus-redis` (Redis 7)

| 层级 | 检查点 | 检查方式 |
|---|---|---|
| 基础 | 容器状态 `running / healthy` | `docker inspect` |
| 基础 | 6379 端口可达 | `docker exec redis-cli ping` → 期望 `PONG` |
| 业务 | 内存使用率（避免 OOM 导致 JWT 丢失） | `redis-cli info memory` |
| 业务 | 持久化配置（RDB/AOF）是否开启 | `redis-cli config get appendonly` |
| 深度 | 能否正常写入/读取（模拟 JWT 存储） | `SET test_key 1 && GET test_key` |

### 3️⃣ `nexus-ollama` (Ollama)

| 层级 | 检查点 | 检查方式 |
|---|---|---|
| 基础 | 容器状态 `running / healthy` | `docker inspect` |
| 基础 | 11434 端口可达 | `curl http://localhost:11434/api/tags` |
| 业务 | **`qwen2.5:7b` 模型已下载**（LLM 主力） | `ollama list \| grep qwen2.5:7b` |
| 业务 | **`nomic-embed-text` 模型已下载**（RAG 向量必需） | `ollama list \| grep nomic-embed-text` |
| 深度 | 模型可实际调用（发一个最小推理请求） | `curl /api/generate -d '{"model":"qwen2.5:7b","prompt":"hi"}'` |
| 深度 | GPU 是否启用（nvidia-smi 能看到 ollama 进程） | 可选，非强制 |

### 4️⃣ `nexus-backend` (Spring Boot 后端)

| 层级 | 检查点 | 检查方式 |
|---|---|---|
| 基础 | 容器状态 `running / healthy` | `docker inspect` |
| 基础 | 8080 端口可达 | `curl localhost:8080/actuator/health` |
| 业务 | **Actuator 健康端点返回 `UP`** | 检查 status 字段 |
| 业务 | 启动日志无 ERROR / FATAL | `docker logs --tail 100 \| grep -iE "error\|fatal"` |
| 深度 | 下游依赖连通性（PG / Redis / Ollama） | 通过 actuator 的 `health` 详情查看 |
| 深度 | AI 网关是否能调通 Ollama | 调一个测试接口（如 `/api/ai/ping`） |

### 5️⃣ `nexus-frontend` (Vue 3 + Nginx)

| 层级 | 检查点 | 检查方式 |
|---|---|---|
| 基础 | 容器状态 `running`（注意：你输出里它只是 `Started`，不是 `Healthy`） | `docker inspect` |
| 基础 | 80 端口可达 | `curl -I localhost` |
| 业务 | `index.html` 能正常返回 200 | `curl localhost \| grep "<div id=\"app\">"` |
| 业务 | **Nginx 反向代理 `/api/` 转发到后端正常** | `curl localhost/api/actuator/health` |
| 深度 | Nginx 错误日志无 502/504 | `docker logs \| grep -E "502\|504"` |

## 🤔 几个需要你确认的点

1. **检查深度**：上面列了三层，脚本里要不要全做？
   - 建议脚本默认只跑 **基础 + 业务层**（深度层用 `--deep` 参数触发），避免每次检查都发真实推理请求浪费资源。

2. **`nexus-frontend` 没有 `Healthy` 状态**：你贴的输出里它只是 `Started`，说明 docker-compose.yml 里**没给它配 healthcheck**。要不要我顺手在 compose 里补一个（比如 `curl -f http://localhost/ || exit 1`）？

3. **检查失败的处理**：某一项失败时，脚本是继续跑完所有检查，还是立刻退出？
   - 建议：**继续跑完**，最后汇总一个"失败清单"，这样排查效率高。

4. **输出格式**：要不要在最后生成一个类似这样的汇总表？
   ```
   ✅ nexus-postgres    : 5/5 通过
   ⚠️  nexus-ollama     : 3/5 通过 (缺失: nomic-embed-text, GPU未启用)
   ❌ nexus-backend     : 2/5 通过 (失败: actuator未响应, 下游PG断连)
   ```

你确认一下这 4 点，我就按确认后的方案出脚本。
