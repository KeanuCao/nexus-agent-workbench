1. 我需要build一个不挂载本地硬盘的wsl系统。这个不需要你操心，我自己就可以搞定。假设名字为nexus-agent-workbench-test
2. 它可以作为github-actions的self-hosted runner， 这个也是我自己手工搞
3. 基本上我想应该可以在github上看到它的存在，并且它可以拉代码
4. 它应该有一个容器是builder和nexus-agent-workbench里面的一样。测试环境所有的容器端口都放到12000到13000之间。
5. 它应该有一个postgrep容器，用来保存测试结果作为查询使用
6. 我先试试Metabase + SQL 视图，可能Metabase也需要容器
7. 我还需要实现一个基于pytest的测试框架，目录应该在第一级建一个test目录，这个阶段只做e2e测试，所以应该有一个ui或者e2e目录用来保存测试脚本
8. 测试引擎用playwright + chrome, 实际呢跑在nexus-agent-workbench-test。
9. 当然你还得设计一下在Windows 11上怎么跑。我的python3是Python 3.14.4，环境用的.venv隔离
10. 测试环境也在nexus-agent-workbench-test里面搭一套吧，不知道会不会和nexus-agent-workbench里面的冲突，如果冲突，就复用nexus-agent-workbench里面的测试环境。如果[text](../../scripts/py/deploy.py)可以复用就好了。
11. 测试结果里面需要就截图来检查脚本正确性
12. 为了快速的生成测试脚本，前端代码需要在可能的地方加上tid，以方便元素的定位, pytest脚本优先使用Role (角色)结合tid来定位元素
比如
```
        <el-form-item label="密码" prop="password">
          <!-- show-password 只影响显示；native-type=submit 让回车与点击走同一条提交路径 -->
          <el-input
            v-model="form.password"
            type="password"
            placeholder="请输入密码"
            autocomplete="current-password"
            show-password
            tid="password"
          />
        </el-form-item>
```
