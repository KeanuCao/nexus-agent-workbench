
## 🧠 核心功能开发清单（请按此顺序执行）

### 阶段0：环境准备与检查 - *目标：一键拉起整套环境*
- 第一步生成 `docker-compose.yml`（PostgreSQL+pgvector / Redis / Ollama / 后端 / 前端 / 打包构建容器，全部容器化，国内镜像加速）。
- 设计 `db-patch` 数据库补丁管理工作流（见上节）。
- 生成环境检查与一键启动脚本（`scripts/check-env.sh`、`scripts/up.sh`），整理 WSL 文档 `wsl.abc.md`。
- 搭建前后端项目骨架。

### 第一阶段：地基搭建 (多租户 + 用户权限) - *目标：跑通登录*
- 生成 Spring Boot 3.x 父 POM，引入 `spring-boot-starter-web`, `mybatis-plus-boot-starter`, `jjwt`。
- 实现基于 **JWT** 的认证过滤器，从请求头获取 Token。
- 实现多租户：数据库表 `t_tenant`，用户表关联 `tenant_id`。
- **交付物**：`/api/auth/login` 接口，登录成功后返回 Token。

### 第二阶段：心脏搭建 (统一 AI 网关) - *目标：对话无阻碍*
- 设计接口 `AiModelService`，实现 `OllamaService`, `DeepSeekService`。
- 使用 **工厂模式 + 策略模式**，根据前端传入的 `modelType` 动态切换。
- 实现 **SSE (Server-Sent Events)** 流式输出，不要用 WebSocket（更轻量）。
- **交付物**：`/api/chat/stream` 接口，前端可以下拉选择"本地Qwen"或"云端DeepSeek"并实时打字机输出。

### 第三阶段：大脑搭建 (RAG 知识库) - *目标：让 AI 读懂文档*
- 引入 `spring-ai-pgvector-store` 或手动编写向量入库逻辑。
- 实现文件上传接口，解析 PDF/Word/TXT (使用 `apache-tika`)。
- 调用 **Ollama Embedding 模型** (`nomic-embed-text`) 将文本分块(Chunk)向量化，存入 pgvector。
- 实现查询接口：接收问题 -> 向量检索 TopK -> 拼接 Prompt -> 调用大模型生成答案。
- **交付物**：知识库页面，上传"公司年报.pdf"，问"去年利润是多少"能准确回答。

### 第四阶段：灵魂搭建 (Agent 编排) - *目标：展示架构视野*
- （不需要做复杂的UI流程图，太耗时）实现一个 **ReAct Agent** 模式。
- 利用 `LangChain4j` 或手写工具调用：定义 `Tools` (如 `getWeather`, `queryDatabase`)。
- 实现多 Agent 协作（模拟 CrewAI）：一个 Agent 负责"搜索"，一个负责"总结"，通过 `CompletableFuture` 串行执行。
- **交付物**：在对话界面输入"先查一下合肥天气，然后用一句话总结"，Agent 自动按顺序执行。

### 测试案例约定（每个阶段强制）
- 每个阶段性任务完成后，**必须**在 `docs/test-cases/` 下生成对应测试案例（TC-00 对应阶段0，依此类推）。
- 测试案例需与功能演进同步维护：功能变更时更新对应 TC 文件，新增功能时新增 TC，保持编号与阶段对应。
