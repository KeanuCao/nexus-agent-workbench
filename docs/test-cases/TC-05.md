### 0.1 无害性总声明（Test Harmlessness —— 先读这一节再看用例）

**跑完本文件之后，被测环境必须与跑之前一致。** 会留痕的只有两样，都在用例内销毁并**自证**；
自证结果写进 `run-results.json` 的 `cleanup` 字段（`ok` / `warn` / `none`）：

| 写什么 | 谁写的 | 为什么非写不可 / 还有谁在消费 | 清理与自证 | 清理失败会怎样 |
|---|---|---|---|---|
| Redis 白名单 **1 个**键 `nexus:auth:token:{jti}`（TTL 7200s） | S1 / S4 / S5 的真登录（走界面） | 对话与知识库接口都不在白名单，没有它就开不了工。消费方：后端鉴权过滤器 | `cleanup_login` 跑完**登出**该 token，并**自证**：用同一个 token 调 `GET /api/auth/me` 期望 **401 + `40101`**（= 过滤器第 ③ 步"白名单里没有它"） | 该键等 TTL 自净；**不阻断任何后续用例**，也**不碰业务数据** ⇒ 记为 `cleanup.login.status="warn"` + 一行显眼说明，**不改变用例主结论** |
| **一份文档**（`知识库说明.txt`，3 块） | 只有 S5 上传 | 本条的验收对象就是"上传 → 入库 → 检索 → 出答案"，只读观察拿不到等价证据。消费方：知识库列表与检索（当前租户） | `kb_doc_registry` 跑前/跑后各取一次**列表指纹**（`documentId`/`fileName`/`chunkCount`），用例内用契约接口删掉自建的那一份（`DELETE /api/kb/documents/{id}`，幂等：回 `10202` 也算"已经没有了"） | 库里多一份 **3KB** 测试文档（列表里带文件名、一眼可辨）；手工删：`DELETE /api/kb/documents/<id>`（id 在 `run-results.json` 的 `cleanup.kb.detail` 里）。**重名不去重**（设计 §10.6）⇒ 下一次重跑不受影响 |

**一律不碰**：业务表数据（`t_user` / `t_tenant` / 既有的知识库文档行）、`db-patch/`、共享卷 `build-artifacts`、
`scripts/`、前端/后端源码、已合入的契约文档。**不删库、不重建容器、不清卷、不改配置**。

**"跑完之后环境与跑之前一致"的判据**：上表两行的自证都通过（`cleanup.*.status` 里没有 `warn`）。
⚠️ 阶段验收还有一条更粗的三判据（容器清单 / `SELECT count(*) FROM t_db_patch` / `git status --porcelain`），
归属 **task.6 的「阶段验收标准」第 7 条**，由主会话在**跑前/跑后各取一次**——不在本文件里。

## 3. 本文件不做的事（覆盖边界与去向）

冒烟是"每跑一次验一次"的最小面，**下面这些刻意不做**，每一项都指回去向：

| 不做 | 为什么 | 去向 |
|---|---|---|
| 逐帧打字机（增量输出） | 需要人眼判"是不是在往外吐"，机器判它要赌时序 | `TC-02-2.4-1` ⑤（人工） |
| 401 自动登出 / token 失效 / 刷新后的假登录态 | 造法要改浏览器存储或服务端登录态，属"按需人工造场景" | `TC-01-1.5-3`、`TC-02-2.4-7`（人工） |
| 上传失败的负路径（类型不支持、扫描版 PDF、超体量） | 一条负路径足够（S2 已代表），负路径多了执行成本翻倍 | `TC-03-3.2-4/3.2-5/3.2-7`（脚本用例） |
| 多轮上下文、跨租户隔离、阈值标定 | 都不是"冒烟"该管的事（成本高、且已被别的用例覆盖） | `TC-02-2.4-2`、`TC-03-4.3`、`TC-03-4.5` |
| 阶段验收的无害性三判据（容器清单 / `t_db_patch` 行数 / `git status`） | 它跨"部署 + 测试"两步，不在单条用例的范围里 | task.6「阶段验收标准」第 7 条（主会话跑前/跑后各取一次） |
| 部署本身（拉起容器、打包、迁移） | 那是 `deploy.py` / 5.1 的事，本工程**不启动、不重建**任何容器 | `scripts/py/deploy.py --profile test` + `.claude/skills/deploy/SKILL.md` |
