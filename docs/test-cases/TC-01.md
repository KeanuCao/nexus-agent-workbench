## 1. JWT 认证过滤器（1.2）

| 用例 | 步骤 | 预期 | 实测 |
|---|---|---|---|
| TC-01-1.2-1 无 token | `curl -s -w '\n%{http_code}' localhost:8089/api/auth/me` | HTTP **401**；body 是 `Result`，`code=40100`，`data=null` | |
| TC-01-1.2-2 伪造 token | 上面加 `-H 'Authorization: Bearer forged.token.value'` | HTTP **401**，`code=40101`（**不是** 40102） | |
| TC-01-1.2-3 过期 token | ① 用 `nexus.jwt.expire-minutes` 改成 `0`（或等其过期）重签一个；② 调 `/api/auth/me` | HTTP **401**，`code=40102` | |
| TC-01-1.2-4 合法 token 放行 | 登录拿 token → 调 `/api/auth/me` | HTTP 200，`code=0`，`data.userId/tenantId` 与登录返回一致 | |
| TC-01-1.2-5 **登出即失效** | ① 登录拿 token；② `POST /api/auth/logout` 带该 token；③ **用同一个 token** 再调 `/api/auth/me` | ② 200 + `code=0`；③ **必须 401 + `code=40101`** | |
| TC-01-1.2-6 白名单放行 | 不带头调 `/api/health` 与 `/actuator/health` | 均**不需要** token（200 / 200 或 503）—— 加了鉴权会让 0.3 的三个脚本全线 FAIL | |

## 2. 多租户隔离（1.3）

| 用例 | 步骤 | 预期 | 实测 |
|---|---|---|---|
| TC-01-1.3-1 **SQL 自动带 tenant_id** | `docker logs nexus-backend` 里找 `/api/auth/me` 触发的查询 | SQL 形如 `... WHERE ... tenant_id = ?`，参数为当前租户；**这是本项验收的判据，必须肉眼看到** | |
| TC-01-1.3-2 两租户互不可见 | ① 用 `admin`（租户 1）的 token 调 `/api/auth/me`；② 换 `demo`（租户 2）的 token 复跑 | 两次返回各自的 `userId` / `tenantId`；**admin 永远拿不到 demo 的数据** | |
| TC-01-1.3-3 `@IgnoreTenant` 生效 | 登录时的 SQL 日志 | **不含** `tenant_id` 条件（登录时尚无租户上下文）；且日志有一行 `租户隔离豁免：...，原因：...` 的 warn 留痕 | |
| TC-01-1.3-4 fail-closed（设计自检） | 由单测覆盖（`TenantContextTest` / 逻辑推演），**不做**运行期用例 —— 造它需要故意写一条漏标注解的查询并重新部署 | 无此用例：记录为「由设计保证 + 单测覆盖」 | 不适用 |

## 3. 登录接口（1.4）

| 用例 | 步骤 | 预期 | 实测 |
|---|---|---|---|
| TC-01-1.4-1 正常登录 | `curl -s -X POST localhost:8089/api/auth/login -H 'Content-Type: application/json' -d '{"username":"admin","password":"admin123"}'` | HTTP 200，`code=0`，`data.token` 非空、`tokenType=Bearer`、`expiresIn=7200`、`data.user.tenantName=默认租户` | |
| TC-01-1.4-2 密码错 | 同上，密码改 `wrong` | HTTP **200**（业务失败走 200），`code=10100`，`msg` 可展示；**响应体无堆栈** | |
| TC-01-1.4-3 用户不存在 | 用户名改 `nosuchuser` | **与 1.4-2 完全同码同文案**（防账号枚举）—— 两条的 `msg` 必须一字不差 | |
| TC-01-1.4-4 账号停用 | `UPDATE t_user SET status=0 WHERE username='demo'` 后登录 `demo` | `code=10101`；**测完把 status 改回 1** | |
| TC-01-1.4-5 租户停用 | `UPDATE t_tenant SET status=0 WHERE tenant_code='demo'` 后登录 `demo` | `code=10102`；**测完改回 1** | |
| TC-01-1.4-6 token 可访问受保护接口 | 拿 1.4-1 的 token 调 `/api/auth/me` | 200 + `code=0` | |

## 4. 前端交互（1.5）

| 用例 | 步骤 | 预期 | 实测 |
|---|---|---|---|
| TC-01-1.5-1 登录成功进控制台 | 浏览器开 `http://localhost:8088`，用 `admin/admin123` 登录 | 落到 `/dashboard`；导航栏显示用户名与租户名 | |
| TC-01-1.5-2 无 token 跳登录 | 清空 localStorage → 直接访问 `/dashboard` | 跳 `/login?redirect=/dashboard`；登录后**回到 `/dashboard`** 而非 `/` | |
| TC-01-1.5-3 401 自动登出 | **刷新页面后**，把 localStorage 里的 token 改坏 → 触发任一受保护请求 | 自动回登录页且 token 被清 | |
| TC-01-1.5-3 备注 | ⚠️ **陷阱**：`/api/health` 是白名单接口、且 store 的内存值是权威 —— 只改 localStorage **不刷新**不会触发 | 见上 | |
| TC-01-1.5-4 已登录访问 /login | 登录状态下直接访问 `/login` | 直接回 `/dashboard`，不出现「登录了还停在登录页」 | |
| TC-01-1.5-5 退出登录 | 点导航栏「退出登录」 | 回登录页；**再点浏览器后退**仍进不去控制台（token 已从服务端失效） | |

## 附：已知的「测不出来」与为什么

| 项 | 为什么不做运行期用例 |
|---|---|
| fail-closed 的实际触发 | 要故意写一条漏标 `@IgnoreTenant` 的查询并重新部署，成本高于收益；由单测 + 设计保证 |
| 401 防抖的真实并发时序 | 需要精确构造并发 401，前端无自动化测试框架（决策 D8），只做了时序推演 |
| Redis 不可用时的全员 401 | 会打断其他用例；需要时单独跑：`docker compose stop redis` → 任何受保护请求应 401 → `start redis` |
